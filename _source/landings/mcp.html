Guardrails before convenience

An assistant with access to production needs limits it can't talk its way around. These are enforced in code, on the server.

SQL guard

No DROP, ALTER, TRUNCATE, CREATE, GRANT, file I/O or multi-statements. Reads capped at 100 rows. Writes off with one variable.

Artisan guard

tinker, db:wipe, migrate:fresh, migrate:reset, long-running servers and more are blocked, and the list is extendable.

Redaction

Env assignments, bearer tokens, DSNs, APP_KEY and provider keys are masked in every answer. env_check returns names, never values.

Tokens and origins

A token per feature, rotated in one command. Browser requests from other hosts are refused. Disabled features answer 404.

Honest annotations

Every tool declares whether it reads, changes or destroys, so your client can ask before acting.

Audit trail

Deploys requested through MCP are recorded in the hash-chained ledger with who asked. The server MCP can't install software or drop data.

Connect in two minutes

Turn the agent's MCP on, create a token, paste one line into your client.

on the server, as the app user
$ php artisan cipi:service mcp --enable
$ php artisan cipi:generate-token mcp
$ php artisan cipi:mcp
# endpoint, tools, and ready-to-paste config
# for Cursor, VS Code, Claude Code and Claude Desktop
on your laptop
# Claude Code
$ claude mcp add --transport http cipi-shop \
    https://shop.example.com/cipi/mcp \
    --header "Authorization: Bearer $CIPI_MCP_TOKEN"
