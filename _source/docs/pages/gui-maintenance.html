Updating — gui update vs gui upgrade

The panel ships as the cipi/gui Composer package, so updates are ordinary Composer updates plus migrations. Two commands cover the common cases:

cipi gui update — soft update

Runs composer update cipi/gui, applies database migrations, and refreshes the compiled theme. This is the day-to-day update path.

bash
cipi gui update

cipi gui upgrade — full rebuild

Rebuilds the panel from scratch. Use it after a major release, or if an environment has drifted and a clean reinstall of the app code is the fastest way back to a known-good state.

bash
cipi gui upgrade

cipi gui refresh-theme — theme only

Recompiles and reloads the panel theme without touching code or the database — handy after a theme tweak.

bash
cipi gui refresh-theme

Operations

cipi gui status

Report the panel's current status — whether it is installed, its domain, and the health of its services.

bash
cipi gui status

cipi gui fix-permissions

Repair the panel's PHP-FPM open_basedir restriction and all runtime file permissions. Run it if the panel starts throwing permission or autoload errors after an update — including the HTTP 500 after cipi gui upgrade / soft update fixed in 5.0.18 (Composer symlink for cipi/gui outside open_basedir).

bash
cipi gui fix-permissions

cipi gui reset-user

Rewrite an administrator's email, name and password, and clear their 2FA enrolment — the recovery path when someone is locked out. reset-password is an alias for the same command. Locked out by SSO-only or a broken provider? cipi gui sso only off brings password sign-in back first.

bash
cipi gui reset-user

Removing the panel — cipi gui remove

Uninstall the panel: its Nginx vhost, PHP-FPM pool, scheduler, application, config and the Let's Encrypt certificate of its domain. A certificate that an app still uses is kept. Your servers and apps are untouched, since the panel is only a client of the API. uninstall is an alias, and --force skips the confirmation prompt. A panel on the Cloudflare tunnel must come off it first (cipi zt hostname remove --gui).

bash
cipi gui remove
cipi gui remove --force

Removing the panel is the ultimate expression of its optionality: uninstall it any time and Cipi is back to a pure CLI, exactly as it was before. The API on each server stays; remove it separately with cipi api remove if nothing else uses it.
