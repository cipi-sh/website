The panel is a standard Laravel application (12 or 13, Livewire 3.6+ or 4) distributed as the cipi/gui package from its own repository (cipi-sh/gui) and installed via a Composer VCS entry tracking dev-main. It lives at /opt/cipi/gui, mirroring how the cipi-api package is bundled.

Because it holds no local queue worker and stores no server state of its own, the panel stays stateless with respect to your infrastructure: it authenticates to each server's API, submits jobs, and polls their status. Tear the panel down and rebuild it elsewhere without touching a single managed server.

API coverage

Panel 4.2.0 uses the routes of API 1.39 on Cipi 5.9.0: GET /api/deploys/last and GET /api/apps/{name}/deploy/history, the Node runtime routes (node-runtimes-manage), /api/backups… (backups-view, backups-manage), database links and the dump upload. A token created with a list of abilities needs the three new ones — the Connections page prints the command — or is a full-access token (cipi api token create --name=gui --full-access). A server on an older API or core keeps every page it had: the Backups tab says what it needs, the Node tab lists and restarts as before, the Last deploy column is left out, and durations come from today's deploy log.

The GUI consumes the Cipi API through 1.33. Panel 3.1 adds Server → Disk: the filesystem /home is on, every app largest first (files, database, total, share of the disk, soft limit — flagged once over the limit or past 90% of it) and every database per engine. It reads GET /api/disk and GET /api/disk/dbs (API 1.33+, Cipi 5.5.2+, ability disk-view). Sizes are measured when the tab opens, so those two requests use their own timeout (180 seconds, CIPI_GUI_HTTP_DISK_TIMEOUT). An older server shows “not available” for that tab. Soft disk limits and Cloudflare DNS accounts have been on the API since 1.32 (the PHP SDK calls them); the panel shows the limit and points at cipi app limits and cipi ssl dns on the host to change them. cipi ssh apps and cipi firewall attempts stay on the host CLI. Keep the panel and each managed server's cipi/api package current (cipi gui update / cipi api update) so create forms and list fields match the server.
