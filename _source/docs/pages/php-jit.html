Turn PHP's JIT compiler on for one app, PHP-FPM or Octane, without touching the others:

bash
cipi app jit myapp on                          # tracing, 128M buffer
cipi app jit myapp on --mode=function --buffer=256M
cipi app jit myapp off
cipi app jit myapp [--json]                    # state, the PHP that answers, supported or not
  • Checked before: the PHP that will run the app is asked to start with JIT in that mode — its CLI for PHP-FPM, the FrankenPHP binary for Octane. An extension that replaces the executor (Xdebug, pcov) or a build without JIT is refused there, before anything is written.
  • Checked after: PHP-FPM has to be active, or Octane answering on its port; otherwise the previous setting is put back and restarted.
  • PHP-FPM: the JIT buffer is shared memory of the FPM of that PHP version (a pool cannot size it), and PHP 8.4 starts with opcache.jit = disable, which a pool cannot undo. While an app on a version has JIT, Cipi makes JIT startable there (conf.d/99-zz-cipi-jit.ini: opcache.jit = off and the largest buffer asked for) and turns it on in that app's pool only. Turning it on or off restarts that version's PHP-FPM — every app on it, for a moment. A value set with cipi ini wins: opcache.jit = disable server-wide makes cipi app jit … on refuse.
  • Octane: FrankenPHP is one process per app, so the settings go in the app's own ini directory (/etc/php/cipi-octane-apps/<app>/).
  • PHP 8.0 or later; not for Node apps. cipi app convert turns JIT off (it was checked for the other runtime). Panel API: GET|PUT /api/apps/{name}/jit.
Measure it on your app. JIT compiles PHP to machine code: CPU-bound work (heavy computation, large collections, templating) gains, a request that spends its time waiting on the database or an API gains little.
