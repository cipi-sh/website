cipi app create supports three app types: Laravel (default), Node (--node=spa|static|ssr, since v5.4.0) and Custom (--custom). Laravel apps get a fully isolated environment: Linux user, PHP-FPM pool or Laravel Octane (FrankenPHP) since v5.0, Nginx vhost, database (MariaDB by default; optional PostgreSQL since v4.8.0), Supervisor worker, crontab entry, Deployer zero-downtime releases, SSH deploy key, and auto-compiled .env. Node apps build a React, Vue, Svelte, Next.js, Nuxt, SvelteKit, Astro or Remix project on every deploy — see Node apps. Custom apps are simpler — see custom apps for details.

Laravel app (default — PHP-FPM)

bash
cipi app create

Since v5.6.0 the wizard opens with numbered menus, the default pre-selected (press Enter to take it): the app type — Laravel, custom, or a Node spa / static / ssr app — then, for Laravel, PHP-FPM or Octane and the database engine (MariaDB or PostgreSQL, when both are installed). The details follow: username, domain, repository, branch, PHP version and an optional asset build such as npm ci && npm run build, which runs inside every deploy before the release goes live (the same setting as cipi app edit --node-build; non-interactive: --node-build=). A Node app asks for its framework (or build/output for a static site). Any type flag (--custom, --octane, --node=, --framework=) skips the menus, and without a terminal every default applies.

Before the summary, the deploy key is tested against the repository (git ls-remote as the app user, branch included). When it cannot read it, the summary says so and, on a terminal, Cipi offers to save or replace the forge token, registers the key and checks again — see Git auto-setup. cipi git check <app> repeats the test later.

Laravel Octane (FrankenPHP)

bash
cipi app create --octane
cipi app create --octane=frankenphp   # explicit (same as --octane)

See Laravel Octane for requirements, convert, and how the vhost differs from FPM. Since v5.10.0 the new app is pinned to the newest FrankenPHP build already on the server, so create downloads nothing; on a server with no build yet the first deploy adopts the one Octane fetches.

Non-interactive (flags)

bash
cipi app create \
    --user=myapp \
    --domain=myapp.com \
    --repository=git@github.com:you/myapp.git \
    --branch=main \
    --php=8.5

# Laravel Octane (FrankenPHP) — v5.0+
cipi app create --user=myapp --domain=myapp.com \
    --repository=git@github.com:you/myapp.git --octane

# optional PostgreSQL (v4.8.0+, after cipi db install pgsql)
cipi app create --user=myapp --domain=myapp.com \
    --repository=git@github.com:you/myapp.git --engine=pgsql

# since v5.9.0 a Laravel app gets a Valkey instance of its own (REDIS_* in its .env);
# --valkey=shared keeps the server's shared instance for this app
cipi app create --user=myapp --domain=myapp.com \
    --repository=git@github.com:you/myapp.git --valkey=shared

# a staging app of the same repository (v5.8.0+): it reads cipi-staging.yml before cipi.yml
cipi app create --user=myapp-stg --domain=staging.myapp.com \
    --repository=git@github.com:you/myapp.git --branch=develop --env=staging
--userLinux username for the app. Must be unique, lowercase, alphanumeric.
--domainPrimary domain (e.g. myapp.com). Used for Nginx vhost and APP_URL.
--repositorySSH Git URL (e.g. git@github.com:you/repo.git). Must be SSH, not HTTPS.
--branchBranch to deploy. Defaults to main.
--envEnvironment label for the app (since v5.8.0): lowercase letters, digits, - and _, at most 32 characters, e.g. production or staging. Defaults to production, which is also what every app created before 5.8.0 is. Cipi writes it to the app's .env as APP_ENV (Laravel apps) and CIPI_ENV (Laravel and Node apps), cipi app show prints it, and it picks the cipi-<env>.yml the app reads before cipi.yml. Change it later with cipi app edit --env=.
--phpPHP version for this app (e.g. 8.5). Defaults to the server's PHP: 8.6 on a server installed with v5.9.1 or later, 8.5 on the ones installed before (or what cipi php switch chose since). Must be an installed version — only 8.3, 8.4 and 8.5 are accepted since v4.5.4 (Deployer 8 requires PHP ≥ 8.3), and 8.6 since v5.9.1.
--octane / --octane=frankenphpServe HTTP via Laravel Octane (FrankenPHP) instead of PHP-FPM (since v5.0). Laravel apps only — rejected with --custom. See Laravel Octane.
--engineDatabase engine: mariadb (default) or pgsql (since v4.8.0; requires cipi db install pgsql). Interactive create prompts when PostgreSQL is installed. Writes matching .env / connection URL.
--node-buildAsset build run inside every deploy, after composer install and before the release goes live, e.g. 'npm ci && npm run build' (Laravel apps; since v5.6.0). Same setting as cipi app edit --node-build and deploy.node_build in cipi.yml. Runners allowed: npm, npx, yarn, pnpm, bun, node.
If a token for the forge (GitHub, GitLab, Bitbucket Cloud, Azure DevOps, Cursor Origin, AWS CodeCommit) is configured, Cipi automatically adds the SSH deploy key and creates the webhook on the repository — no manual steps needed. See Git auto-setup for setup instructions and fallback options when auto-configuration is not available.
