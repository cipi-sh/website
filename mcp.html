Two servers, two scopes

Install one, or both. Each has its own endpoint, its own token and its own limits.

Agent MCP: inside one app

For debugging and shipping an app. Installed with the Cipi Agent package.

Endpoint
https://shop.example.com/cipi/mcp
Install
composer require cipi/agent
Tools
health app_info deploy_status logs db_schema db_query artisan env_check cipi_yml deploy anonymizer
Plus
panel_* tools with the PHP SDK: rollback, DB backup, audit
Docs: agent MCP

Server MCP: the whole server

For operating servers. Part of the Cipi API, on its own subdomain.

Endpoint
https://api.example.com/mcp
Install
cipi api api.example.com
Tools
Apps, deploys and audit, aliases, www, SSL, redirects, proxies, Node, databases, search, limits, disk, cipi.yml, PHP, services, logs, jobs
Token
One with mcp-access
Docs: server MCP

Guardrails before convenience

An assistant with access to production needs limits it can't talk its way around. These are enforced in code, on the server.

SQL guard

No DROP, ALTER, TRUNCATE, CREATE, GRANT, file I/O or multi-statements. Reads capped at 100 rows. Writes off with one variable.

Artisan guard

tinker, db:wipe, migrate:fresh, migrate:reset, long-running servers and more are blocked, and the list is extendable.

Redaction

Env assignments, bearer tokens, DSNs, APP_KEY and provider keys are masked in every answer. env_check returns names, never values.

Tokens and origins

A token per feature, rotated in one command. Browser requests from other hosts are refused. Disabled features answer 404.

Honest annotations

Every tool declares whether it reads, changes or destroys, so your client can ask before acting.

Audit trail

Deploys requested through MCP are recorded in the hash-chained ledger with who asked. The server MCP can't install software or drop data.

Connect in two minutes

Turn the agent's MCP on, create a token, paste one line into your client.

on the server, as the app user
$ php artisan cipi:service mcp --enable
$ php artisan cipi:generate-token mcp
$ php artisan cipi:mcp
# endpoint, tools, and ready-to-paste config
# for Cursor, VS Code, Claude Code and Claude Desktop
on your laptop
# Claude Code
$ claude mcp add --transport http cipi-shop \
    https://shop.example.com/cipi/mcp \
    --header "Authorization: Bearer $CIPI_MCP_TOKEN"

Questions

Which assistants work?

Any MCP client: Claude Code, Claude Desktop, Cursor, VS Code with Copilot, and others that support Streamable HTTP or a stdio bridge.

Can the assistant break production?

Destructive SQL (DROP, ALTER, TRUNCATE, GRANT), multi-statements and dangerous Artisan commands (migrate:fresh, db:wipe, tinker…) are blocked; database writes can be switched off; secrets are masked in every answer.

Does my data go to Cipi?

No. Both MCP servers run on your own server. What your assistant's vendor sees is what you ask it and what the tools return, already redacted.

Do I need both servers?

No. The agent's MCP is enough to debug and deploy an app. Add the server MCP when you want the assistant to create apps, issue certificates or manage databases.

What's the difference between the App MCP and the Server MCP?

The App MCP lives inside one Laravel app (installed with composer require cipi/agent) and sees that app: its logs, schema, data, Artisan and deploys. The Server MCP is part of the Cipi API and sees the whole server: every app, domains, certificates, databases, backups, PHP. See MCP servers and the API.

Can I make the assistant read-only?

Yes. Set CIPI_MCP_DB_WRITE=false for the App MCP, and give the Server MCP a token without write abilities. Destructive host operations aren't available through MCP at all.

Will it run a migration or a deploy without asking?

Every tool declares whether it reads, changes or destroys. Clients such as Claude Code and Cursor use that to ask you before running anything that changes data. Deploys are also recorded in the audit ledger with who asked.

Does the assistant see passwords or API keys?

No. env_check returns variable names only, and every tool's output is redacted before it leaves the server: env values, bearer tokens, DSNs, APP_KEY and provider keys are masked.

How do I revoke access?

Rotate the app token with php artisan cipi:generate-token mcp, or revoke the server token with cipi api token revoke. The old token stops working immediately.

Is it safe to point it at production?

That's what it's built for, with guards enforced on the server. Start read-only, add write access when you trust the workflow, and give it anonymized data when it needs to experiment.

Do I need a paid AI plan?

You need an MCP-capable client. Cipi's MCP servers are free and self-hosted; what your AI client costs depends on its vendor.
