Install the panel

Requirements, install, SSL, domain changes and two-factor login.

Web panel
Install the panel
$ cipi api api.example.com
$ cipi gui panel.example.com

Requirements#

The panel talks to servers only through the Cipi API. Before installing it:

You needDetails
A Cipi server to host itOne of the servers you manage, or a small dedicated box
A hostname of its owne.g. panel.example.com, with an A/AAAA record pointing at that server. It can't share a hostname with an app or with the API (api.example.com); Cipi refuses a taken domain
cipi api on every managed serverWith a full-access token, see API setup
bash
cipi api token create --name=gui --full-access   # every ability, including future ones

PHP, the FPM pool, the Nginx vhost and the scheduler are provisioned by the installer: no Laravel setup by hand.

Install: cipi gui <domain>#

bash
cipi gui panel.example.com
Step 1 of 4DNS check

The panel's domain (e.g. panel.example.com) must already point at this server, or the certificate can't be issued. The installer checks it first.

Step 2 of 4Provision

Cipi creates the panel's own PHP-FPM pool, Nginx vhost and cron, isolated from your apps.

Step 3 of 4First admin

You choose the first administrator's e-mail and password. More users and roles come later, from the panel.

Step 4 of 4Certificate

A Let's Encrypt certificate is issued and HTTPS is enforced. Open the URL and log in.

The app is bundled at /opt/cipi/gui; settings go to /etc/cipi/gui.json. The admin password needs 12+ characters with upper and lower case, a digit and a symbol, and no more than 4 identical characters in a row.

FlagUse it when
--skip-dns-checkBehind a NAT or proxy the check can't see through
--no-sslYou'll issue the certificate later with cipi gui ssl

SSL: cipi gui ssl#

Issues (or re-issues) the Let's Encrypt certificate and switches the panel to HTTPS, for a certificate skipped with --no-ssl or one that failed. It checks DNS first, exits 1 if certbot fails, and renews with the same automation as app domains.

bash
cipi gui ssl

Change domain: cipi gui move#

bash
cipi gui move panel.newdomain.com           # move and issue the new certificate
cipi gui move panel.newdomain.com --no-ssl  # certificate later
What happensDetail
KeptAccounts, 2FA enrolments, server connections (admins sign in again)
VhostRewritten; if nginx -t rejects it, the old one comes back and nothing changes
Config/etc/cipi/gui.json and APP_URL updated
SSLOld certificate deleted, new one issued; on failure the panel stays on HTTP until cipi gui ssl

Managed servers need no change: the panel calls their API URLs, and their allowlists are by IP. To move a server's API, use cipi api move there and update its URL under Connections.

With Cloudflare Zero Trust: run cipi zt hostname remove --gui before the move, then cipi zt hostname add --gui and cipi zt access enable --gui. The move refuses to run while the hostname is on the tunnel.

Two-factor authentication#

Session login with optional TOTP per user (Google Authenticator, 1Password, Aegis…), enrolled from the profile. With single sign-on, MFA is the identity provider's job and the TOTP step is skipped for SSO sign-ins.

Lost a second factor? From the server, cipi gui reset-user rewrites the account and removes the enrolment.
