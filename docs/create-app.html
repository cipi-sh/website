Create an app

The cipi app create wizard and its flags for Laravel, Node and custom apps.

Apps

One command creates a complete, isolated app: Linux user, PHP pool (or Octane), Nginx vhost, database, worker, scheduler, deploy key and a ready .env.

The app wizard
$ cipi app create

Pick the app type#

TypeForFlag
Laravel (default)Laravel apps, on PHP-FPM or Octanenone, or --octane
NodeReact, Vue, Svelte, Next.js, Nuxt, SvelteKit, Astro, Remix--node=spa|static|ssr
CustomWordPress, plain PHP, static files, SFTP-only sites--custom

Details per type: Laravel Octane, Node apps, Custom PHP & static sites.

Interactive#

bash
cipi app create

The wizard asks, with the default pre-selected (Enter accepts it): app type, PHP-FPM or Octane, database engine, then name, domain, repository, branch, PHP version and an optional asset build. Before the summary it tests the deploy key against the repository; if it cannot read it, it offers to save a Git token and register the key for you.

With flags#

Any type flag skips the menus; without a terminal every default applies.

bash
cipi app create --user=myapp --domain=myapp.com \
    --repository=git@github.com:you/myapp.git --branch=main --php=8.6

# Octane, PostgreSQL, front-end build
cipi app create --user=api --domain=api.myapp.com \
    --repository=git@github.com:you/api.git --octane --engine=pgsql \
    --node-build='npm ci && npm run build'

# A staging copy of the same repository
cipi app create --user=myapp-stg --domain=staging.myapp.com \
    --repository=git@github.com:you/myapp.git --branch=develop --env=staging
FlagMeaningDefault
--userLinux user and app name: unique, lowercase, alphanumericasked
--domainPrimary domain; sets the vhost and APP_URLasked
--repositoryGit URL over SSH (git@…)asked (required for Laravel)
--branchBranch to deploymain
--phpAn installed PHP version (8.3–8.6)server default
--octaneServe with Octane (FrankenPHP) instead of PHP-FPMoff
--enginemariadb or pgsql (after cipi db install pgsql)mariadb
--valkeyshared to use the server's Valkey instead of the app's ownown instance
--node-buildAsset build run in every deploy (npm, npx, yarn, pnpm, bun, node)none
--envEnvironment label: sets APP_ENV and picks cipi-<env>.ymlproduction

After creation#

The summary shows the server IP for DNS, the deploy key, the database credentials with a mariadb+ssh:// URL for TablePlus or DBeaver, and the webhook URL and token. It is shown once.

Step 1 of 5Save the summary

The summary shows the database password, the deploy key, the webhook URL and token. It is shown once: copy it to your password manager now.

Step 2 of 5Deploy key on Git

The deploy key must be added to the repository as a read-only deploy key. With a Git provider token saved (cipi git github-token …), Cipi did it already.

Step 3 of 5Point DNS

Create an A record for the domain pointing at the server's IP. Check with dig +short myapp.com.

Step 4 of 5cipi deploy

cipi deploy myapp builds the first release: clone, Composer, migrations, swap. Then open http://myapp.com.

Step 5 of 5cipi ssl install

Once DNS points at the server, cipi ssl install myapp issues the certificate and switches APP_URL to https://.

With a Git provider token configured, the deploy key and the push webhook are added to the repository automatically. See Git providers & deploy keys.

In the web panel#

Create an app from the browser: the same wizard, with a server picker. The web panel is optional; everything here also works from the CLI.

Common problems#

ProblemFix
--repository refusedUse the SSH form: git@github.com:you/app.git, not https://
Name refusedLowercase letters and numbers only, unique on the server
--engine=pgsql refusedInstall PostgreSQL first: cipi db install pgsql
Domain already usedEach hostname belongs to one app; remove it from the other app first

Questions#

QuestionAnswer
I lost the creation summary.cipi app show myapp shows domain, deploy key and webhook; cipi db password myapp makes a new database password.
Laravel, custom or Node?Laravel for Laravel apps, Node for front ends (Next, Nuxt, Vite…), custom for WordPress, plain PHP and static sites.
Can I change the PHP version later?Yes: cipi app edit myapp --php=8.6, with zero downtime.
