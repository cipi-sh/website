Panel overview

What the panel does, with a tour of every screen.

Web panel

Cipi is CLI-first, and always will be. The web panel is an optional layer for people who prefer a browser: your team, a client, or you on a phone. It's a self-hosted Laravel app that drives one or many Cipi servers through the same REST API as the CLI client and WHMCS. No proprietary control plane, no SaaS, no extra cost.

Real screens of the panel, in motion. Pick a clip, or let them play. Every screen is in the tour below.

Skip it and nothing changes. Without the panel Cipi stays a lean CLI: no daemon, no web surface, nothing extra listening. Anything done in the browser can be done in the terminal, and the other way round.

  • Browserpanel.example.com
  • cipi/guiLaravel app on one Cipi server
  • Cipi APIapi.<server>, one per managed server
  • cipi CLIdoes the work, as on SSH

Light and dark themes, a phone layout, a time zone per account. A server with an older API or a narrower token keeps working for everything it supports; where it lacks something, the panel says to update Cipi on it (cipi self-update && cipi api update) and which abilities the token needs.

Permissions are checked on every request, server-side, against the app, server and job the page works on. Installing software outside the closed package catalog, monitor thresholds, changes to the Cloudflare tunnel, downloading a backup run, starting a self-update and the CrowdSec rescue stay on the CLI by design, and the server refuses to close its own SSH, 80 and 443 to the panel.

Screenshot tour#

Real screenshots of the panel against its demo environment: three fictional servers, documentation-range domains and IPs (./dev/demo.sh in the package).

Apps#

Every app of every server in one list, with server and type filters, search and a deploy button per row.

Creating an app starts with its type. Node presets (Next.js, Nuxt, SvelteKit, Astro, Remix, Vite) fill the same defaults as cipi app create --node.

App detail#

A header with status, type, runtime, the server and its IP, and actions, then one tab per area. Tabs live in the URL (?tab=deploy), so they can be bookmarked.

The Overview's details say where to connect and as whom: the app's Linux user — the one that signs in over SSH and SFTP, named after the app — the server's IP and the ssh shop@203.0.113.24 command made of the two. A click copies each. The IP is the one the panel keeps for the server, typed on Connections or read from its status, so this works with any Cipi version; the command uses the default SSH port.

Jobs#

Deploys, SSL and database operations run as async jobs. The overlay polls GET /api/jobs/{id}, shows elapsed time and colour-codes the output; closing it leaves the job running.

A job that fails says why in one line above its output, and a failed deploy adds what to check. A deploy stopped because a step ran out of time — the front-end build has 30 minutes, every other step 5 — names the step and how long it ran. The panel follows a deploy for as long as it runs: the API gives one two hours.

Databases and server#

Backups, transfers and updates#

Backups starts here on a server without them: Set up backups — a nightly profile takes every app and every database and keeps them on the server. Then S3 buckets and SFTP servers are added on a par. See set up.

Then: what each profile takes, against every app and database; the destinations — the server's disk, and S3 buckets and SFTP servers on a par. While backups are only on the server, the tab says so. Add an S3 bucket: a provider fills in the endpoint and the region; the server reaches the bucket with the keys before it saves anything, and the secret key goes to it once, on its standard input — the panel keeps nothing. Adding a bucket or an SFTP server lists the profiles to send there too, the ones that keep their runs on the server only ticked. Edit leaves a key or a secret empty to keep the one the server has.

Add an SFTP server makes the key on the server and shows its public half with the command that installs it on the remote — ssh-copy-id -s for a Hetzner Storage Box, whose preset fills in port 23 — then Test writes a file there and removes it. See SFTP destinations. Encryption key: Show the key (logged and notified on the server) and Rotate. Stored runs: Preview the retention and Apply the retention.

Transfer sends the apps of the server to another one — server sync as a wizard, the connection checked before anything moves, the archive encrypted with a passphrase the servers make and keep to themselves.

Updates has the optional safeguards of self-update: a delay — here 12 hours, with a release waiting for it — and Install only signed releases, which says it is not available yet: Cipi releases are not signed at the moment.

Metrics#

The Metrics tab of a server and of each app: charts from 1 hour to 30 days with releases and incidents marked, uptime per day and the events timeline, refreshed every 30 seconds while open. See metrics.

Notifications#

Every channel of the server and which events reach it. Secrets never come back to the panel; an empty secret field keeps the stored one. See notifications.

Firewall#

UFW, Fail2ban and CrowdSec of the server on one tab: the rules in UFW's order with Kept open on SSH, 80 and 443 and the Cipi feature that owns each one, blocked addresses, everything banned right now with Unban, the SSH login threshold and CrowdSec with its allowlist. Viewing needs a level on the server, changing needs Manage. See firewall.

Zero Trust#

Both sides of Zero Trust on one tab. On top, the server's Cloudflare Tunnel as the CLI set it up: healthy, degraded or down, every connector with its addresses, the locks, and each hostname with who may open it — read-only, every change to the tunnel stays on cipi zt. See Cloudflare Zero Trust.

Under it, the mesh network — Tailscale or NetBird — is managed from the page: join a network with its key, see the server's address on it and the last SSH login that came over it, close SSH and 80/443 to the world, turn Tailscale SSH on, leave. A button the server would refuse — nobody has signed in over the mesh yet, the panel would lose the server — is greyed out, with the server's reason beside it. See Tailscale & NetBird.

Infrastructure#

The providers around your servers, from the same panel: 28 connectors, with any number of accounts each. Every address that is a server of the panel says which one; a DNS record takes a server's name and is saved with its IP.

Connections and security#

Team and roles#

Admins see and do everything. A user gets what an admin grants and is invited with a copyable link that works once and expires after seven days. An admin can require two-factor authentication for every account: the list then shows who still has to set it up.
