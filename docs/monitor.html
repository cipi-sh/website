Server monitor

Disk, certificates, services, workers and 5xx checks.

Backups & monitoring

The server watches itself every 5 minutes and tells you when something actually breaks. No agent, no third-party service: a cron job, a few state files and your notification channels. For the history behind the alerts — CPU, memory, requests, 5xx and uptime over days — see Metrics: every change of state of a check below is recorded there as an event.

Server monitor
$ cipi monitor
bash
cipi monitor                    # run every check now (exit 1 on warn/crit)
cipi monitor list               # checks, thresholds, state, last alert
cipi monitor set disk --warn=85 --crit=95
cipi monitor disable load
cipi monitor test               # sample alert to every channel

The checks, on by default#

CheckWatchesAlerts when
diskEvery local filesystem≥80% warn, ≥90% critical
app_diskApps with a soft disk limit≥90% of the limit, then over it
sslLet's Encrypt certificates≤14 days to expiry, or expired
servicesNginx, databases, PHP-FPM, Valkey, Supervisor, Fail2ban…Any unit not active
workersQueue workers and HorizonA process not running
http_5xxNew lines in each app's access log≥20 errors and ≥5% of requests
fs/etc/cipi, /var/log/cipiNo longer writable (read-only remount)
load1-minute loadAbove 4× the cores for 2 runs in a row
tunnelThe Cloudflare Tunnel, when Zero Trust is onDegraded (warn); cloudflared stopped, or Cloudflare sees the tunnel down or inactive (critical)
meshThe mesh network — Tailscale or NetBird — while the server is on oneThe node key expires within 14 days, or the coordination server can't be reached (warn); the client stopped, the server off the network, the node key expired (critical)

Tune any threshold: --ssl --days=21, http_5xx --count=50 --ratio=10, load --factor=6 --runs=3, app_disk --minutes=30.

Alerts without noise#

State changeMessage
ok → warn/criticalOne alert
warn ↔ criticalOne escalation
Still failingA reminder every 4 hours (set reminder --minutes=N, min 15)
failing → okOne recovery, with how long it lasted

The 5xx check reads only what was written since the last run and starts with a baseline, so it never alerts on old errors. A check that can't run reports critical instead of crashing. Each check has its own trigger and can be muted (cipi notifications disable monitor_load).

Questions#

QuestionAnswer
What is checked?Load, memory, disk, services, backups, certificates, security updates, health checks, every 5 minutes.
Can I see how it went over time?Yes: Metrics keeps every minute for 7 days and 15-minute summaries for 30, with charts in the panel.
Errors inside my code?Use an exception tracker such as Boogle.
