CLI Client

Installing cipi-cli

cipi-cli is a standalone Go binary that talks to the Cipi REST API from your local machine. No SSH required — manage apps, deployments, SSL, databases (including anonymized dumps), PHP versions, services, SSH keys, SMTP and healthchecks from any terminal. Binaries are available for Linux and macOS (amd64 and arm64).

The Cipi server must have the API package installed and configured before using cipi-cli. See cipi api for setup instructions.

Download binary

Download the latest release for your platform from the Releases page, then:

bash
chmod +x cipi-cli-*
sudo mv cipi-cli-* /usr/local/bin/cipi-cli

Build from source

bash
git clone https://github.com/cipi-sh/cli.git
cd cli
make build
sudo make install

Verify installation

bash
$ cipi-cli version
cipi-cli v1.5.0 (linux/amd64)

CLI Client

Configuration

A profile is a named connection to one Cipi server (API endpoint + token). Use as many profiles as you have servers — for example prod, staging, or client-a. You need the API endpoint URL and a Sanctum token created with cipi api token create on each server.

Credentials are stored per profile in ~/.cipi/config.json with permissions 0600. Always pass a profile name — if you omit it, the CLI prompts for one instead of silently writing to default.

Interactive setup

Recommended: store the token with api token add. Equivalent helpers are configure --profile and profiles add:

bash
$ cipi-cli api token add prod
Cipi API endpoint: https://api.example.com
API token: 1|yourtoken...
Server profile "prod" saved → ~/.cipi/config.json

$ cipi-cli api token add staging
Cipi API endpoint: https://staging-api.example.com
API token: 1|stagingtoken...
Server profile "staging" saved → ~/.cipi/config.json

# Same flow via configure / profiles add
$ cipi-cli configure --profile prod
$ cipi-cli profiles add staging

Non-interactive setup

bash
$ cipi-cli api token add prod \
    --endpoint https://api.example.com --token "1|yourtoken..."

$ cipi-cli profiles add staging \
    --endpoint https://staging.example.com --token "1|yourtoken..."

Show configuration

bash
$ cipi-cli profiles show prod
Profile:   prod
Endpoint:  https://api.example.com
Token:     1|a8Kz...4f2a

$ cipi-cli profiles show
# Shows all configured server profiles

CLI Client

profiles

Manage multiple server connections from a single cipi-cli installation. One profile equals one server. Prefix any command with a profile name to target that server, or set a default with profiles use to omit the prefix. The aliases servers / server work the same as profiles.

Targeting a server

bash
$ cipi-cli prod apps list
$ cipi-cli staging apps show myapp
$ cipi-cli prod deploy myapp
$ cipi-cli prod ssl install myapp

With a default server set, you can run commands without the prefix:

bash
$ cipi-cli profiles use prod
Default profile set to "prod"

$ cipi-cli apps list
# Uses the prod profile

$ cipi-cli staging apps list
# Explicit prefix still targets staging
Command Description
cipi-cli api token add [profile] Add or update API endpoint + token for a named server profile
cipi-cli profiles List configured servers (alias: cipi-cli servers)
cipi-cli profiles add [name] [flags] Add or update a server profile (same as configure --profile)
cipi-cli profiles list List configured servers
cipi-cli profiles show [profile] Show one server profile, or all if omitted
cipi-cli profiles use <profile> Set the default server (alias: profiles default)
cipi-cli profiles delete <profile> [-y] Delete a local server profile (credentials only — nothing changes on the remote server)

api token add, profiles add, and configure accept the same flags: --endpoint and --token (plus --profile when the name is not positional).

Aliases: servers / server → profiles; profiles use → profiles default. The same management commands are also available under cipi-cli configure list, configure show, configure default, and configure delete — prefer profiles or api token add for storing credentials.

apps

Manage applications on your Cipi server.

Command Description
cipi-cli apps list List all applications
cipi-cli apps show <name> Show application details
cipi-cli apps create [flags] Create a new application
cipi-cli apps edit <name> [flags] Edit an application
cipi-cli apps delete <name> [-y] Delete an application
cipi-cli apps suspend <name> Take an app offline (HTTP 503 maintenance page) without deleting it
cipi-cli apps unsuspend <name> Restore a suspended app to normal service
cipi-cli apps logs <name> [flags] Read paginated application logs (nginx, PHP-FPM, Laravel, worker, deploy)
cipi-cli apps fix-permissions <name> Restore the app home permissions (Cipi 5.2.1+)
cipi-cli apps artisan <name> [command...] Run an Artisan command as an async job (Cipi 5.0.3+)
cipi-cli apps run <name> [command...] Run a whitelisted app binary — see cipi-cli run-commands (Cipi 5.0.3+)
cipi-cli apps env show|set <name> Read .env, or merge keys with --set KEY=VALUE / --unset KEY (Cipi 5.0.3+)
cipi-cli apps auth show|create|update|delete <name> Manage the shared Composer auth.json (Cipi 5.0.3+)
cipi-cli apps basicauth status|enable|disable <name> HTTP Basic Auth in front of the app (--user, --password; auto-generated when omitted)
cipi-cli apps node status|restart <name> Node app status and blue-green restart (Cipi 5.4.0+)
cipi-cli apps search enable|disable <name> Meilisearch / Laravel Scout for one app (Cipi 5.2.2+)
cipi-cli apps webhook recreate <name> [--rotate-secret] Recreate the Git deploy webhook, optionally rotating CIPI_WEBHOOK_TOKEN (Cipi 5.0.6+)

Alias: app → apps. The artisan, run, env and auth subcommands need the matching token abilities (apps-artisan, apps-run, apps-env, apps-auth) and a Laravel app — custom apps have no .env or Artisan.

Create flags

--user Application name (used as Linux user and database name)
--domain Primary domain for the application
--php PHP version (e.g. 8.5)
--repository Git repository URL
--branch Git branch to deploy from
--custom Create a custom (non-Laravel) app with htdocs deploy
--docroot Document root relative to htdocs (custom apps only)
--engine Database engine: mariadb or pgsql (Cipi 4.8+)
--octane Laravel Octane mode: true, false or frankenphp (Cipi 5.0+)
--node Create a Node app: spa, static or ssr (Cipi 5.4.0+). A repository is required and --php is not accepted
--framework Node framework preset: next, nuxt, sveltekit, astro, remix or vite
--node-version Node major version (e.g. 22 or 24)
--build Node build command
--start Node start command (SSR apps)
--output Node build output directory (spa / static apps)
--health-path Node health path checked during blue-green restarts (SSR apps)

Edit flags

--php Change PHP version
--repository Update Git repository URL
--branch Change deploy branch
--domain Rename the primary domain (requires Cipi 4.6.2+ and API 1.9.0+)
--node … --node, --node-version, --build, --start, --output, --health-path — update the Node app settings listed under create flags

Logs flags

--type Log type filter: all (default), nginx, php, worker, deploy, or laravel
--page Page number, starting at 1 for the most recent lines (default 1)
--per-page Lines per log file per page (default 50, max 1000; requires API 1.11.9+)

Examples

bash
# List all apps
$ cipi-cli apps list

# Create a Laravel app
$ cipi-cli apps create --user=myapp --domain=myapp.com \
    --php=8.5 --repository=git@github.com:acme/myapp.git --branch=main

# Create a custom (non-Laravel) app
$ cipi-cli apps create --user=landing --domain=landing.acme.com \
    --custom --docroot=dist

# Edit an existing app
$ cipi-cli apps edit myapp --php=8.4

# Suspend staging for maintenance
$ cipi-cli apps suspend staging

# Read recent deploy logs (page 1 = newest lines)
$ cipi-cli apps logs myapp --type=deploy

# Paginate older nginx lines
$ cipi-cli apps logs myapp --type=nginx --page=2 --per-page=100

# Run Artisan, read and update .env
$ cipi-cli apps artisan myapp migrate --force
$ cipi-cli apps env show myapp
$ cipi-cli apps env set myapp --set APP_DEBUG=false --unset OLD_KEY

# Create a Node SSR app
$ cipi-cli apps create --user=web --domain=web.acme.com --node=ssr --framework=next \
    --repository=git@github.com:acme/web.git --branch=main

# Recreate the Git webhook with a new secret
$ cipi-cli apps webhook recreate myapp --rotate-secret

# Delete an app (skip confirmation)
$ cipi-cli apps delete myapp -y

redirect / proxies

Whole-app and path redirects, plus prefix reverse proxies — the remote side of cipi redirect and cipi proxy. Requires Cipi 5.4.1+ (API sudoers, API 1.31+) and the redirects-view|manage / proxies-view|manage abilities. Aliases: redirects → redirect, proxy → proxies.

Command Description
cipi-cli redirect list <app> List the whole-app redirect and every path redirect
cipi-cli redirect set <app> --to URL [--code 301] [--keep-path] Redirect the whole app to a URL (one hop; path and query kept unless --keep-path=false)
cipi-cli redirect enable|disable <app> Toggle the whole-app redirect without removing it
cipi-cli redirect unset <app> Remove the whole-app redirect
cipi-cli redirect add <app> --from /path --to URL [--code] [--keep-path] Add a path redirect — a trailing slash on --from means prefix match
cipi-cli redirect remove <app> --from /path Remove a path redirect
cipi-cli proxies list <app> List prefix reverse proxies
cipi-cli proxies add <app> --prefix /api --upstream URL [flags] Proxy a path prefix to an upstream (--strip-prefix, --preserve-host, --timeout 60, --buffering)

# Proxy /api to an internal service
$ cipi-cli proxies add myapp --prefix /api --upstream http://127.0.0.1:8080 --strip-prefix
$ cipi-cli proxies list myapp

Anonymized dumps (cipi/agent)

The anonymizer is not part of the Cipi API: it lives in the cipi/agent package inside the Laravel app. The CLI reads the app URL (APP_URL, else https://<primary domain>) and CIPI_ANONYMIZER_TOKEN from the app .env through the API (apps-view + apps-env abilities), then calls POST /<CIPI_ROUTE_PREFIX>/db on the app itself. The agent runs the job in the app queue and emails a signed download link valid for 15 minutes.

bash
# One-time setup on the app (all through the Cipi API)
$ cipi-cli apps artisan myapp cipi:service anonymize --enable
$ cipi-cli apps artisan myapp cipi:generate-token anonymize
$ cipi-cli apps artisan myapp cipi:init-anonymize
# then edit /home/myapp/.db/anonymization.json on the server

# Request a dump — the signed link arrives by email
$ cipi-cli prod db anonymize myapp --email dev@example.com
✓ Anonymization job queued for 'myapp'

# Download it: default name from the server, -o - streams to stdout
$ cipi-cli db anonymize download "https://myapp.com/cipi/db/<token>?expires=…&signature=…" -o myapp.sql
$ cipi-cli db anonymize download "<signed url>" -o - | mysql -u root myapp_local
--email, -e Address that receives the signed download link (prompted when omitted)
--url Override the app base URL, e.g. when the app redirects to www — redirects are never followed
--token Override the bearer token read from .env
--output, -o download: output file (- for stdout)
--force, -f download: overwrite an existing file
Requires cipi-cli 1.5.0+, Cipi 5.0.3+ / API 1.14+ (for apps env) and cipi/agent 1.1.1+ with the anonymizer enabled in the app. Custom and Node apps are refused. Every failure names the fix — anonymizer disabled, missing token, missing anonymization.json, invalid token, or an app that redirects (pass --url). Links expire after 15 minutes; request a new dump when they do.

Command Description
cipi-cli health list All configured app healthchecks and their state

CLI Client

update

Update cipi-cli to the newest release from GitHub. The command picks the highest semver among published releases (not GitHub’s “latest” flag, which can point at an older tag), downloads the matching binary for your platform, verifies its SHA-256 checksum, and replaces the running binary in place. Aliases: self-update, upgrade.

Command Description
cipi-cli update Update to the highest published semver
cipi-cli update --force Reinstall even if already up to date (allows downgrade)
bash
$ cipi-cli update
Downloading cipi-cli v1.5.0...
Checksum verified. Updated to v1.5.0.

# Aliases work the same
$ cipi-cli self-update
$ cipi-cli upgrade

# If installed in a system path, use sudo
$ sudo cipi-cli update

CLI Client

completion

Install shell autocompletion for cipi-cli. The recommended path is completion install, which detects your shell, writes the completion script, and hooks it into your rc file (idempotent).

Command Description
cipi-cli completion install Auto-detect shell and install completion
cipi-cli completion install --shell zsh Install for a specific shell (zsh, bash, or fish)
cipi-cli completion zsh Print the zsh completion script to stdout
cipi-cli completion bash Print the bash completion script to stdout
cipi-cli completion fish Print the fish completion script to stdout
bash
$ cipi-cli completion install
Installing zsh completion...
Completion installed → ~/.cipi/completions/cipi-cli.zsh
Hooked into ~/.zshrc

# Or pin a shell explicitly
$ cipi-cli completion install --shell bash

For zsh and bash, the script is written under ~/.cipi/completions/ and a source line is appended to your shell rc file. For fish, the script goes to ~/.config/fish/completions/ (auto-loaded). Reload the shell afterwards, then try cipi-cli <TAB>.

Releases

Releases are automated via GitHub Actions. Pre-built binaries for Linux (amd64/arm64) and macOS (amd64/arm64) are published with SHA-256 checksums on the GitHub Releases page.

Source code

cipi-cli is open source, MIT licensed, and written in Go. Contributions welcome on GitHub.

CLI Client

Requirements

The Cipi server must have the API package installed and configured before using cipi-cli:

bash
$ cipi api <domain>
$ cipi api ssl
$ cipi api token create

New app PHP versions must be 8.3, 8.4, or 8.5 (Cipi 4.5.4+). Some CLI features depend on specific server and API versions:
