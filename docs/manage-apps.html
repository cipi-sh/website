Manage apps

List, inspect, edit, clone and delete apps; set a default app.

Apps

Everything you do to an app after creating it: inspect, change, convert, clone, delete. Every change is applied in place, with zero downtime where the runtime allows it.

Inspect#

CommandShows
cipi app listEvery app: domain, PHP, status (suspended when offline)
cipi app show myappDomain, PHP or Node mode, environment, workers, deploy key, webhook, redirects, proxies

Change#

cipi app edit flags can be combined in one call.

CommandWhat happens
cipi app edit myapp --php=8.6Moves pool, vhost, workers, cron, deploy recipe and .env to the new PHP. No downtime
cipi app edit myapp --domain=new.example.comNew primary domain; the old one becomes an alias; vhost, APP_URL, webhook and certificate follow
cipi app edit myapp --branch=developDeploy another branch (also updates CIPI_DEPLOY_BRANCH)
cipi app edit myapp --env=stagingNew environment label: APP_ENV, CIPI_ENV, and reads cipi-staging.yml
cipi app edit myapp --repository=git@…Attach or change the repository (e.g. turn an SFTP site into a Git one)
cipi app edit myapp --node-build='npm ci && npm run build'Front-end build in every deploy; --no-node-build removes it
cipi app edit myapp --node-version=24Pin Node for this app's builds; default follows the server
cipi app edit myapp --predeploy-snapshotDump the database before every deploy (Safe deploy)
cipi app convert myapp --to=octane|fpmSwitch runtime (Laravel Octane)
cipi app jit myapp on|offPHP JIT for this app (PHP JIT)

On an Octane app, changing PHP moves CLI, cron and workers at once; web workers follow when you pin a matching FrankenPHP build.

Credentials#

CommandEffect
cipi app reset-password myappNew SSH/SFTP password for the app user, shown once
cipi app reset-db-password myappNew database password, written to .env in the same step
cipi app webhook recreate myapp --rotate-secretRecreate the Git webhook with a new secret

Delete#

bash
cipi app delete myapp            # asks for confirmation
cipi app delete myapp --force    # for scripts

Removes the user, files, database, vhost, PHP pool, workers, search keys and every rule Cipi created for the app. Back up first if you might need the data.

A default app: cipi use#

Working on one app for a while? Set it once and leave the name out.

bash
cipi use shop
cipi deploy            # → shop (default app — cipi use)
cipi app logs --type=php
cipi use --clear

It is stored on the server; CIPI_APP=shop sets it for one shell only. For safety, destructive commands (app delete, password resets, convert, clone, db …) always require the name, and commands that mean "all apps" without a name keep that meaning.

Clone an app#

Make a staging or review copy of a Laravel app with its own domain, user and (optionally) a fresh database.

bash
cipi app clone myapp --domain=staging.myapp.com --name=myapp-stg \
    --branch=develop --env=staging --with-db
FlagMeaning
--domainRequired. The clone's domain
--nameLinux user for the clone
--branch / --envDeploy branch and environment (default: the source's)
--with-db / --no-dbCreate a fresh database, or none

A clone never talks to production by accident: it gets its own Reverb credentials, its own search key and prefix (production search keys are not copied), and no webhook or Git IDs from the source.

Repair permissions#

bash
cipi app fix-permissions myapp   # one app
cipi app fix-permissions         # every app

Restores the layout Cipi created, after an archive unpacked as root or a careless chmod:

PathModeWhy
Home750Nginx (in the app group) can read; other apps cannot
.ssh700SSH refuses a deploy key with looser permissions
shared/.env640Secrets readable by the app only
logs/2775 setgidNginx writes logs as www-data
storage/775Laravel writes cache and uploads

Also available as a button in the web panel.
