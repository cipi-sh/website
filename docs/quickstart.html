Quickstart

From a fresh VPS to a Laravel app on HTTPS in five commands.

Start hereEdit on GitHub

This page takes you from a fresh Ubuntu VPS to a Laravel app on HTTPS. Each step shows the commands and what they print; click a terminal to skip to the end of it. You need a VPS with Ubuntu 24.04 or 26.04 and a public IP, a domain whose DNS you can change, and a Git repository.

1. Install Cipi on the server#

SSH into the fresh server as root (or a sudo user) and run the installer. It asks for your SSH public key first, shows its plan, and sets up the stack in about ten minutes. Details, requirements and the non-interactive variant are in Install Cipi.

Install on a fresh Ubuntu server
$ wget -O - https://cipi.sh/setup.sh | bash

2. Log in as the cipi user#

Root login over SSH is disabled after the install. Connect as cipi with your key and prefix commands with sudo, which works without a password for cipi only.

From your laptop
$ ssh cipi@203.0.113.10
$ sudo cipi status

3. Create your first app#

The interactive wizard starts with numbered menus, the default pre-selected: the app type (Laravel, custom, or a Node spa / static / ssr app), then for Laravel PHP-FPM or Octane (FrankenPHP) and the database engine (MariaDB or PostgreSQL). It then asks for a username, primary domain, Git repository URL (SSH format) and branch when applicable, PHP version, and an optional asset build such as npm ci && npm run build that runs inside every deploy. Laravel apps always require a repository; for custom apps you can leave the repository empty to host the site via SFTP only — see custom apps. Before the summary Cipi tests the deploy key against the repository and, when it cannot read it, offers to save the forge token and registers the key for you.

cipi app create
$ sudo cipi app create
bash
cipi app create
cipi app create --octane   # Laravel Octane (FrankenPHP)

Or pass all flags directly to skip interactive mode:

bash
cipi app create \
    --user=myapp \
    --domain=myapp.com \
    --repository=git@github.com:you/myapp.git \
    --branch=main \
    --php=8.5

At the end, Cipi prints a credentials summary — save it, shown only once — including the server's public IP address (for DNS configuration), the SSH deploy key, database credentials, a ready-to-use mariadb+ssh:// connection URL for GUI clients (TablePlus, DBeaver, Sequel Pro), webhook URL, and webhook token.

4. Add the deploy key to your Git provider#

If you have configured a token for your Git provider via cipi git — GitHub, GitLab, Cursor Origin, AWS CodeCommit, Bitbucket Cloud or Azure DevOps since v5.2.3 — this step is automatic — Cipi adds the deploy key and creates the webhook for you. See Git auto-setup for details.

Otherwise, copy the ssh-ed25519 ... key shown after app creation and add it as a Deploy Key in your repository, then confirm with cipi git check myapp:

  • GitHub: Repository → Settings → Deploy keys → Add deploy key
  • GitLab: Repository → Settings → Repository → Deploy keys
  • Bitbucket Cloud: Repository settings → Access keys
  • Azure DevOps: User settings → SSH public keys

5. Prepare your Laravel project#

Cipi uses the database driver for cache, sessions, and queues. A Laravel 11+ skeleton already ships those migrations; on an older project run these once, commit, and push the generated migrations:

bash
php artisan cache:table
php artisan session:table
php artisan queue:table
php artisan migrate
Cipi automatically runs artisan migrate --force on every deploy. The cache, session, and queue tables will be created on first deploy if you commit the migrations.

Why not Valkey (Redis) by default? Cipi installs Valkey on every server, but it is one instance with one password for all the apps of the server: an app that has it can read, and flush, the cache, sessions and queues of every other app. The database driver keeps each app inside its own database and user. Valkey is a deliberate choice per app — faster queues and cache, Horizon, Reverb scaling — and how to switch, with a distinct REDIS_PREFIX per app, is in Valkey. The phpredis extension is already installed.

6. Deploy#

bash
cipi deploy myapp

Deployer clones your repo into a new releases/N/ directory, runs composer install --no-dev, links .env and storage/, runs migrations, runs artisan optimize, creates storage:link, swaps the current symlink atomically, and restarts queue workers. Zero downtime.

cipi deploy
$ sudo cipi deploy myapp

7. Install SSL#

bash
cipi ssl install myapp

Certbot obtains a Let's Encrypt certificate for the domain and its aliases, Cipi writes the HTTPS vhost (HTTP redirects to HTTPS) and updates APP_URL in .env. Your Laravel app is now live on https://myapp.com. The DNS of every name must already point to the server and port 80 must be open.

cipi ssl install
$ sudo cipi ssl install myapp

Behind the Cloudflare proxy, prefer cipi ssl install myapp --dns=cloudflare (works with the proxy on) and set SSL/TLS to Full (strict) — never Flexible. Subdomains for tenants (*.myapp.com): see Wildcard domains & SSL.

8. Optional: add the web panel#

If you or your clients prefer a browser, install the REST API and the panel. Each needs its own domain pointed at the server. The panel can then manage this server and any other Cipi server you connect. See Install the panel.

API and panel
$ sudo cipi api api.example.com
$ sudo cipi gui panel.example.com
