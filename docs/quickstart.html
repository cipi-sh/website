Quickstart

From a fresh VPS to a Laravel app on HTTPS in five commands.

Start here

From a fresh Ubuntu server to a Laravel app on HTTPS, in about fifteen minutes. Every step shows the real command and what it prints; click a terminal to jump to the end.

  1. Installone command on the server
  2. Log inas cipi, with your SSH key
  3. Create an appisolated user, DB, PHP
  4. Deployzero downtime from Git
  5. HTTPSLet's Encrypt, auto-renewed

You need: an Ubuntu 24.04 or 26.04 VPS with a public IP, a domain whose DNS you control, and a Git repository. Cipi is free; the only cost is the server.

1. Install Cipi#

SSH into the fresh server as root (or a sudo user) and run the installer. It asks for your SSH public key, shows its plan, then installs and hardens the whole stack.

Install on a fresh Ubuntu server
$ wget -O - https://cipi.sh/setup.sh | bash

Save the credentials it prints. Requirements, SSH keys and unattended installs: Install Cipi.

2. Log in as cipi#

Root login over SSH is now off. Connect as cipi with your key and prefix commands with sudo (no password needed for cipi).

From your laptop
$ ssh cipi@203.0.113.10
$ sudo cipi status

3. Create your first app#

The wizard asks for the app type, runtime, database, name, domain and repository, then builds an isolated app: its own Linux user, database, PHP pool, Nginx vhost, worker and deploy key.

cipi app create
$ sudo cipi app create

Skip the questions with flags:

bash
sudo cipi app create --user=myapp --domain=myapp.com \
    --repository=git@github.com:you/myapp.git --branch=main

The summary at the end (database password, deploy key, webhook token, a mariadb+ssh:// URL for TablePlus or DBeaver) is shown once. Save it.

4. Connect the repository#

If you gave the installer a Git token, there is nothing to do: Cipi added the deploy key and the push webhook to the repository. Otherwise add the ssh-ed25519 … key from the summary as a read-only deploy key:

ProviderWhere
GitHubRepository → Settings → Deploy keys
GitLabSettings → Repository → Deploy keys
BitbucketRepository settings → Access keys
Azure DevOpsUser settings → SSH public keys

Then check that the server can read it: sudo cipi git check myapp. Tokens and automatic setup: Git providers.

5. Prepare the Laravel project#

Cipi keeps cache, sessions and queues in each app's own database, so no app can read another's data. Laravel 11+ ships those tables; on an older project create them once and commit:

bash
php artisan cache:table && php artisan session:table && php artisan queue:table

Migrations run on every deploy. Prefer Valkey for speed or Horizon? Switch per app in Valkey.

6. Deploy#

cipi deploy
$ sudo cipi deploy myapp

The new release is built in its own folder, migrated, then made live with one atomic symlink swap. Visitors never see a half-deployed app, and cipi deploy myapp --rollback goes back in a second. How it works: Deploy & roll back.

7. Turn on HTTPS#

Point the domain's DNS at the server, then:

cipi ssl install
$ sudo cipi ssl install myapp

The certificate covers the domain and its aliases and renews itself. Behind the Cloudflare proxy use --dns=cloudflare and set SSL/TLS to Full (strict). More in SSL certificates.

8. Optional: the web panel#

Prefer a browser, or need one for clients? Install the API and the panel, each on its own domain. The panel can manage this server and any other Cipi server you connect.

API and panel
$ sudo cipi api api.example.com
$ sudo cipi gui panel.example.com

Common problems#

ProblemFix
Permission denied (publickey) when logging inLog in as cipi (not root) with the key you pasted in the installer: ssh cipi@IP
The installer stops: container detectedChoose a full virtual machine (KVM), not an LXC/OpenVZ container
Deploy fails reading the repositoryAdd the deploy key to the repository, then sudo cipi git check myapp
Certificate failsDNS must point at the server first: dig +short myapp.com
500 error after the first deploysudo cipi app logs myapp --type=laravel shows the reason; often a missing .env key

Questions#

QuestionAnswer
How long does it take?About 10 minutes for the install, a few minutes per app.
Never used a server?Read VPS, SSH and DNS basics first, then the full first-deploy guide.
