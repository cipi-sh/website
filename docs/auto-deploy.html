Auto-deploy on push

The signed webhook that deploys when you push.

Deploy

Push to your branch and the app is live a minute later. The Git provider calls a signed webhook on your app; the deploy itself runs on the server as the app user. CI needs no SSH key and the server opens no extra port.

A push deploys
$ git commit -am "checkout: round tax per line" && git push
$ ssh cipi@203.0.113.10 sudo cipi deploy shop --history --limit=1

How it works#

Step 1 of 5git push

You push commits to the app's deploy branch (main by default). Pushes to other branches are acknowledged and ignored.

Step 2 of 5Provider → /cipi/webhook

GitHub, GitLab, Bitbucket, Gitea or Azure DevOps call the app's webhook URL over HTTPS, signed with the app's secret.

Step 3 of 5Verify & queue

Cipi checks the signature and the branch. If both are right it leaves a small trigger and answers 200 immediately, so the provider never times out.

Step 4 of 5Cron, within a minute

A cron job checks for triggers every minute and starts the deploy as the app's own Linux user, never as root.

Step 5 of 5Deploy

From here it's a normal deploy: new release, Composer, migrations, atomic swap, workers restarted. You get the usual notification.

The webhook only drops a trigger file; it never runs the deploy itself. That keeps the HTTP answer instant (providers time out after ~10 s) and the deploy in the same safe context as cipi deploy.

ReceiverUsed byVerifies
Cipi Agent (cipi/agent)Laravel appsGitHub/Bitbucket HMAC, GitLab/Azure token, Gitea/Forgejo signature
Built-in receiverNode appsGitHub/Bitbucket HMAC, GitLab/Azure token

Set it up#

bash
# in your Laravel project
composer require cipi/agent && git commit -am "Add Cipi Agent" && git push
# on the server: one manual deploy, so the route exists
cipi deploy myapp
cipi git status                 # webhook already created?
cipi deploy myapp --webhook     # if not: URL and secret to add by hand
ProviderPayload URLSecretEvents
GitHubhttps://myapp.com/cipi/webhookthe token from --webhookpush
GitLabsameSecret token: same valuePush events

Only pushes to CIPI_DEPLOY_BRANCH deploy; others get skipped. Cipi keeps it in step with cipi app edit --branch. Use HTTPS (cipi ssl install) so the secret never travels in clear text.

Verify with a small commit:

bash
cipi deploy myapp --status
cipi app logs myapp --type=deploy

Every webhook deploy lands in the audit ledger with pusher, commit, delivery ID and source IP.

From any tool, not only Git#

The agent's webhook also accepts the secret as a Bearer token, so anything that can send an HTTP request can queue a deploy: a CI job, a scheduler, a chat bot.

bash
curl -fsS -X POST https://myapp.com/cipi/webhook \
    -H "Authorization: Bearer $CIPI_WEBHOOK_TOKEN" -H "Content-Type: application/json" \
    -d '{"ref":"refs/heads/main","pusher":{"name":"release-bot"}}'
{"status":"queued","app":"myapp","provider":"webhook","branch":"main", …}

It queues the deploy and answers at once; it doesn't wait for the result. When a pipeline must know whether the deploy worked, use SSH or the API instead: CI/CD pipelines.

200 but no deployAnother branch was pushedCheck CIPI_DEPLOY_BRANCH
