Disk usage

Disk usage for the server and for each app.

Backups & monitoringEdit on GitHub

Available since v5.5.0. cipi monitor tells you the disk is filling up; cipi disk tells you who is filling it. It prints every local filesystem, then every app, largest first, in GB and as a share of the disk. The same reading from your laptop is cipi-cli disk (cipi-cli 1.6.0+, API 1.33+, ability disk-view; the server needs 5.5.2+ so the API may run cipi disk).

bash
cipi disk                        # the server, then every app
cipi disk db                     # every database, engine by engine, in MB
cipi disk --json                 # same figures for scripts (also: cipi disk db --json)
cipi app limits shop --disk=10   # soft limit: alert at 90% and when over, block nothing
output
  Server disk
  MOUNT                          SIZE         USED         FREE     USE
  /                         100.00 GB     40.00 GB     60.00 GB     40%

  Apps (3) — % of the 100.00 GB on /
  APP                           FILES     DATABASE        TOTAL    DISK  LIMIT
  shop                        2.00 GB      1.00 GB      3.00 GB    3.0%  10 GB (30%)
  blog                        0.50 GB     120.4 MB      0.62 GB    0.6%  —
  front                       0.10 GB      0.00 GB      0.10 GB    0.1%  —
  All apps                                              3.72 GB    3.7%
  Everything else                                      36.28 GB   36.3%
Column What it measures
FILES The app's home: releases, shared storage, logs
DATABASE The database named after the app and, when shared/.env points DB_DATABASE at another one, that one too. The size is what the server reports (information_schema for MariaDB, pg_database_size for PostgreSQL); for MariaDB it is compared with the database's directory in the data dir and the larger of the two is used. If the server does not answer, the directory alone is measured. Custom and Node apps have no database and show 0.
TOTAL / DISK Files plus database, and that total as a percentage of the filesystem that holds /home
LIMIT The app's soft disk limit and how much of it is used — over once passed, — when the app has none
Everything else The rest of the used space: system, packages, logs, local backups, databases that belong to no app

Sizes below 0.01 GB are printed in MB (4.2 MB), so a small database does not read as 0.00 GB. --json carries the exact files_kb, database_kb and total_kb next to the rounded GB, plus limit_gb, limit_percent and over_limit for every app. Sizes are measured with du when the command runs — nothing is stored — so a server with large apps takes a few seconds. Read-only, root CLI; cipi help server and tab-completion know it.

cipi disk db — every database, in MB#

Next to the per-app figure, a listing of the databases themselves, for every engine installed on the server. It shows what the app table cannot: databases that belong to no app, and the engines that are not SQL.

output
  MariaDB
  DATABASE                                               SIZE
  blog                                                 2.0 MB
  shop                                               200.0 MB
  On disk, whole engine                              500.0 MB

  Valkey
  DATABASE                                     KEYS      SIZE
  db0                                          1204         —
  Memory in use                                       12.3 MB
  On disk, whole engine                                3.0 MB

  Meilisearch
  INDEX                                   DOCUMENTS      SIZE
  shop-products                               12000    8.4 MB
  On disk, whole engine                               45.0 MB
  • MariaDB — one row per database, empty ones included. The size is the larger of what the server reports and the database's directory in the data dir, since the files include space the server has not handed back. These are the figures the DATABASE column of cipi disk uses.
  • PostgreSQL — one row per database (pg_database_size).
  • Valkey — one row per logical database (db0, db1, …) with its number of keys. Valkey does not know the size of a single database, so the size is the instance's: memory in use and files on disk. The password reaches valkey-cli through the environment, not the command line.
  • Meilisearch — one row per index with its number of documents, and the size of its documents where the installed version reports it. The total is the data.ms directory.

Every engine closes with its size on disk as a whole (data directory, logs included). An engine that is installed but does not answer gets a note and still shows that total; an engine that is not installed is left out.

A soft disk limit per app#

No app has a limit until you give it one — the default is unlimited, on new and existing servers alike. A limit is a number of GB for files and database together (the TOTAL column), set with cipi app limits <app> --disk=<GB>. It is soft: nothing is blocked when it is passed and the app keeps working. The limit is a threshold for the app_disk monitor check, which warns at 90% of it, goes critical once the app is over, and sends a recovery when it is back under — through email and every chat channel, trigger monitor_app_disk.

A hard limit (filesystem quotas) is deliberately not part of this: it cannot cover the database, needs quotas enabled on the filesystem, and takes a site down when it is reached. The whole-server alert did not change: the disk check has warned at 80% and gone critical at 90% of any filesystem since 5.3.0, on by default.
