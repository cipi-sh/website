Artisan, commands & logs

Run Artisan, Tinker and shell commands; read app logs.

AppsEdit on GitHub

cipi app run#

Since v5.0.3, run a whitelisted non-interactive command as the app user — useful from the CLI, panel API, and web GUI “App commands”. Editors, pagers, shells, and REPLs are blocked (nano, vim, less, bash, tinker, …). Interactive flags (e.g. tail -f, php -a) are rejected.

bash
cipi app run myapp composer install --no-dev
cipi app run myapp npm ci
cipi app run myapp ls -la shared
cipi app run --commands          # list allowed binaries
cipi app run --commands --json

Allowed binaries include composer, npm/npx/yarn/pnpm, ls/ll, cat/head/tail, filesystem helpers, archives, git, php, node, and find. REST: POST /api/apps/{name}/run (async job, ability apps-run) and GET /api/run-commands (API 1.14+). MCP: AppRun, AppRunCommands.

v5.0.4+ fixed /usr/bin/env: '--': No such file or directory — every whitelisted command (including GUI App commands) failed before that patch. Run cipi self-update.

app artisan & app tinker#

Run Artisan commands and Tinker as the app user with the correct PHP version and open_basedir context — exactly as they would run during a deploy.

bash
cipi app artisan myapp migrate:status
cipi app artisan myapp queue:retry all
cipi app artisan myapp db:seed --class=ProductionSeeder
cipi app artisan myapp cache:clear
cipi app tinker myapp

cipi app logs#

Tail application logs in real-time. By default, all logs are shown, including the Laravel log in shared/storage/logs/. Logs are rotated daily by logrotate and kept according to the retention policy.

bash
cipi app logs myapp                  # all logs (incl. the Laravel log)
cipi app logs myapp --type=nginx     # Nginx access + error
cipi app logs myapp --type=php       # PHP-FPM errors
cipi app logs myapp --type=worker    # queue worker output
cipi app logs myapp --type=deploy    # deploy history
cipi app logs myapp --type=laravel   # Laravel application logs
--type=nginxNginx access and error logs
--type=phpPHP-FPM error log
--type=workerSupervisor / queue worker output
--type=deployDeployer output — full deploy history with timestamps
--type=laravelLaravel application logs from shared/storage/logs/ (laravel.log since v5.5.0)

One laravel.log, rotated once (v5.5.0+)#

Up to 5.4, cipi app create wrote LOG_CHANNEL=daily into every Laravel app's .env, so Laravel wrote one file per day (laravel-2026-09-24.log) — and the cipi-app-logs logrotate rule then rotated each of those files once more, a day or two later. The content moved to laravel-<date>.log.1, which was never compressed and never deleted, so the 12-month retention did not apply to Laravel logs; and the empty laravel-<date>.log left behind is the file cipi app logs --type=laravel and the panel read, so the log looked empty while the entries sat next to it.

Since v5.5.0 apps log to a single storage/logs/laravel.log, and logrotate alone rotates it: daily, compressed from the second day, 365 rotations.

  • New apps get LOG_CHANNEL=single in shared/.env.
  • Existing apps are switched by the 5.5.0 migration, which also folds the dated files into laravel.log.
  • The logrotate pattern is now storage/logs/*[!0-9].log, which leaves out any log whose name ends in a date. An app that sets LOG_CHANNEL=daily again on purpose gets what Laravel does by itself: one file per day, pruned after LOG_DAILY_DAYS. Every other .log in storage/logs is rotated as before.
