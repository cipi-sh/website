Wildcard domains

Tenant subdomains with a wildcard certificate.

Domains & SSL

One app answering on every <tenant>.myapp.com, with one certificate for all of them. It takes two separate things:

PartHowNote
Routingcipi alias add myapp '*.myapp.com' (or a wildcard primary)Works with any DNS
Certificatecipi ssl install myapp --dns=cloudflareLet's Encrypt issues wildcards over DNS only; Cipi automates Cloudflare

Which setup is yours#

Your DNSCertificateCloudflare SSL/TLS mode
Cloudflare, proxied (orange) — best for SaaSLet's Encrypt via DNS-01, or Cloudflare Origin CAFull (strict)
Cloudflare, DNS only (grey)Let's Encrypt via DNS-01not used
Another providerMove DNS to Cloudflare (free), list the subdomains, or bring your own certificate—
Cloudflare Tunnel (cipi zt)Not needed: Cloudflare terminates HTTPSset by the tunnel

With Cloudflare, step by step#

Step 1 of 5DNS records

In Cloudflare, create A @ and A * records pointing at the server's IP, both with the same proxy status. The * record sends every subdomain to the server.

Step 2 of 5API token

Create a Cloudflare API token with only Zone → DNS → Edit on that zone and save it with cipi ssl dns set --token=….

Step 3 of 5Wildcard alias

cipi alias add myapp '*.myapp.com' (with quotes) tells Nginx to send every subdomain to this app.

Step 4 of 5Certificate

cipi ssl install myapp --dns=cloudflare proves ownership with a temporary DNS record and gets the wildcard certificate in about a minute. It works with the proxy on or off.

Step 5 of 5Proxy settings

If the records are proxied (orange cloud): SSL/TLS Full (strict), no rule that sets Flexible, cipi zt enable for real visitor IPs and trustProxies in Laravel.

bash
cipi ssl dns set --token=YOUR_CLOUDFLARE_TOKEN
cipi alias add myapp '*.myapp.com'
cipi ssl install myapp --dns=cloudflare
cipi ssl status
curl -sI https://tenant1.myapp.com | head -1

Renewals happen by themselves with the same token, through DNS, so they don't depend on the proxy, on Cloudflare rules or on port 80. --wildcard adds myapp.com + *.myapp.com to the certificate even without a wildcard alias (handy for many explicit subdomains); it does not route anything.

How the proxy fits in#

DNS only (grey cloud)Proxied (orange cloud)
Visitors connect toYour serverCloudflare, which connects to your server
Certificate visitors seeCipi's Let's Encrypt certificateCloudflare's edge certificate (Universal SSL, automatic)
Certificate on the serverCipi's, checked by browsersCipi's, checked by Cloudflare in Full (strict)
SSL/TLS mode in CloudflareIgnoredFull (strict)
Server IPPublicHidden behind Cloudflare
CDN, WAF, DDoS protectionNoYes
IP seen by Nginx and LaravelThe visitor'sCloudflare's, until you configure real IPs

With the orange cloud every request makes two HTTPS hops: browser → Cloudflare (edge certificate) and Cloudflare → server (Cipi's certificate). Both must be valid for every tenant name, and both cover one level: myapp.com and *.myapp.com.

Start grey. When https://tenant1.myapp.com works with the grey cloud, switch @ and * to orange together. One change at a time makes errors easy to place.

DNS records#

In DNS → Records:

TypeNameContentProxy status
A@server IPv4Proxied or DNS only
A*server IPv4Same as @
AAAA@, *server IPv6Only if the server really answers on IPv6; same status
  • Keep @ and * on the same proxy status. Mixed statuses make the apex and the tenants behave differently (different certificates, different IPs in logs), and errors become hard to place.
  • The wildcard only fills gaps. A name with a record of its own (api, www, mail) doesn't use *. That's how you point api.myapp.com elsewhere, but it also means a stray record silently takes a tenant name away.
  • Proxied wildcards are on every plan, Free included.
  • Mail stays grey. MX, SPF, DKIM and DMARC records are unaffected by *, but hostnames for mail servers (mail., smtp.) must be DNS only: the proxy carries only HTTP(S).
  • No AAAA you can't serve. Cloudflare may prefer IPv6 to reach the origin: a wrong AAAA gives intermittent 52x errors.
  • Wait until the zone shows Active in Cloudflare before issuing the certificate: with the old nameservers still answering, the DNS challenge fails.

The API token#

My Profile → API Tokens → Create Token, template Edit zone DNS:

FieldValue
PermissionsZone → DNS → Edit
Zone ResourcesInclude → Specific zone → myapp.com
Client IP Address FilteringEmpty, or only the server's IP

Use an API token, never the Global API Key (full access to the whole account). The token is stored root-only in /etc/cipi/cloudflare/; a client with its own Cloudflare account gets a named token (--name=client-a, then --account=client-a, see SSL).

SSL/TLS settings, when proxied#

SSL/TLS → Overview, encryption mode:

ModeCloudflare → your serverWith Cipi
OffNo HTTPS at allDon't
FlexibleHTTPRedirect loop: Cipi redirects HTTP to HTTPS, Cloudflare asks again over HTTP, forever
FullHTTPS, certificate not checkedWorks, but an attacker in between wouldn't be noticed
Full (strict)HTTPS, certificate checked against the hostnameUse this

Then SSL/TLS → Edge Certificates:

SettingSet toWhy
Universal SSLActiveThe edge certificate for myapp.com and *.myapp.com
Always Use HTTPSOnCloudflare redirects HTTP itself, before reaching the server
Minimum TLS Version1.2Drops only very old clients
Automatic HTTPS RewritesOnFixes leftover http:// links
HSTSOnly after every tenant works over HTTPSWith includeSubDomains it covers all tenants, and browsers remember it for months

Rules override the global mode. A Configuration Rule or Page Rule that sets SSL to Flexible for some hostnames gives redirect loops only on those names, typically "the apex works, tenants loop". Check Rules before anything else.

Let's Encrypt or Cloudflare Origin CA#

Let's Encrypt is the safer default: it keeps working if you ever switch a record to grey. Origin CA fits servers that are permanently behind the proxy or the tunnel.

Real IPs and a closed origin#

Behind the orange cloud every request comes from a Cloudflare IP. Left as is, Nginx logs, Fail2ban, CrowdSec and Laravel ($request->ip(), rate limiting, login throttling) see the same few addresses for every visitor.

  1. Nginx: cipi zt enable sets Nginx's real IP from Cloudflare's ranges (refreshed daily) and teaches Fail2ban and CrowdSec the same ranges. It closes no port and routes nothing through the tunnel, so it's safe on its own.
  2. Laravel: trust the proxy in bootstrap/app.php:
php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->trustProxies(at: '*');
})
  1. Optional, close the origin: cipi zt lock http --yes allows 80/443 only from Cloudflare, so nobody can skip the WAF by calling the server's IP. It refuses while an app still renews over HTTP; with --dns=cloudflare renewals are unaffected. Don't lock if some records are grey.

trustProxies(at: '*') is safe only when the server can't be reached except through Cloudflare (step 3, or a tunnel). With 80/443 open to the world, list Cloudflare's IP ranges instead of *, or anyone can fake their IP.

Caching, WebSockets and limits#

TopicWhat to know
HTML cacheCloudflare doesn't cache HTML by default: keep it that way. Never "Cache Everything" on tenant pages: users would see each other's pages
Static filesCached per hostname, so each tenant has its own copy. To share one copy, serve assets from one host (ASSET_URL=https://myapp.com)
WebSocketsReverb works through the proxy on 443, on every plan
Upload size100 MB per request on Free and Pro: larger uploads go straight to object storage with signed URLs
Request timeoutAbout 100 seconds: long exports and imports belong in queues
WebhooksDon't challenge /cipi/webhook with Bot Fight Mode or WAF rules, or push-to-deploy stops

Check it#

bash
# Through Cloudflare: expect HTTP/2 200 and "server: cloudflare"
curl -sI https://tenant1.myapp.com | grep -Ei '^(http|server)'
# Straight to the server, skipping Cloudflare: checks Cipi's certificate and vhost
curl -sI --resolve tenant1.myapp.com:443:SERVER_IP https://tenant1.myapp.com | head -1
# Names on the server's certificate: expect myapp.com and *.myapp.com
echo | openssl s_client -connect SERVER_IP:443 -servername tenant1.myapp.com 2>/dev/null | openssl x509 -noout -ext subjectAltName

If the second command works and the first doesn't, the problem is in Cloudflare (mode, rules, DNS). If both fail, it's on the server (alias, certificate).

The whole Cloudflare setup, not only wildcards, is in Cloudflare in front of Laravel.

Without Cloudflare#

OptionWhen
Move DNS to Cloudflare, records "DNS only"Recommended: free, traffic unchanged
List each subdomain as an alias, HTTP-01Few, known tenants (max 100 names per certificate)
Bring your own certificate with your provider's certbot pluginRoute 53, DigitalOcean, OVH, Gandi…
bash
# bring your own: name the certificate after the app's primary domain
apt install python3-certbot-dns-route53
certbot certonly --dns-route53 -d myapp.com -d '*.myapp.com' --cert-name myapp.com
cipi alias add myapp '*.myapp.com'    # Cipi finds and serves it

Don't run cipi ssl install on that app afterwards: it would reissue over HTTP without the wildcard.

Multi-tenant tips#

  • Exact names win: with *.myapp.com on one app, api.myapp.com can still be another app.
  • Unknown hosts are closed by the default server, not sent to your tenant resolver.
  • Laravel: resolve the tenant from the Host header; set SESSION_DOMAIN=.myapp.com only to share logins across subdomains.
  • Need isolation per tenant (own database, backups, server)? Create one Cipi app per tenant through the API instead.
