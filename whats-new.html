The deepest Laravel hosting CLI yet — optional Laravel Octane (FrankenPHP) beside classic FPM, optional PostgreSQL beside MariaDB, plus Horizon, Reverb, and production ops that used to mean a SaaS panel.

Get started Octane docs

Since v5.0

Laravel Octane

Serve HTTP with FrankenPHP instead of PHP-FPM — create with cipi app create --octane, convert any Laravel app with cipi app convert --to=octane. FPM and Octane coexist on the same VPS.

Since v4.8

PostgreSQL

MariaDB stays the default. Install Postgres with cipi db install pgsql, then pick per app with --engine=pgsql. Both engines, one CLI.

v5.0

Latest · 5.0.1 August 4, 2026

Cipi 5 turns your Ubuntu VPS into a full Laravel production platform — Octane, queues with Horizon, WebSockets with Reverb, wildcard SSL, staging clones, and healthchecks — all from the CLI (and the optional panel API / GUI).

  • Laravel Octane (FrankenPHP)

    cipi app create --octane allocates a localhost port, proxies Nginx to a Supervisor-managed Octane process, and keeps static assets on disk. Convert existing apps with cipi app convert <app> --to=octane|fpm. See Laravel Octane docs.

  • Laravel Horizon

    cipi worker horizon enable|disable|status — mutually exclusive with classic queue:work workers. Deploys run horizon:terminate and restart the Supervisor program cleanly.

  • Laravel Reverb

    First-party WebSockets with cipi app reverb enable|disable|status — localhost port, Supervisor process, Nginx /app proxy, and REVERB_* in .env.

  • Scheduler CLI

    Manage the crontab entry with cipi schedule on|off|status <app>.

  • Node build on deploy

    cipi app edit --node-build='npm ci && npm run build' runs your frontend build after Composer vendors (fail-closed). Disable with --no-node-build.

  • App cloning for staging

    cipi app clone <src> --domain=… spins up a staging (or review) app — optional DB copy, shared branch settings, no copied webhook/git IDs.

  • Pre-deploy DB snapshots

    Opt-in dumps before deploy via cipi deploy --snapshot or --snapshot-required. Code rollback does not auto-restore the database.

  • Per-app resource limits

    cipi app limits sets FPM children, memory, Octane workers, and queue process caps with hard ceilings enforced by Cipi.

  • SSL DNS-01 (Cloudflare)

    Wildcard and DNS-validated certs: cipi ssl dns set --provider=cloudflare --token=… then cipi ssl install <app> --dns=cloudflare [--wildcard]. HTTP-01 remains the default.

  • HTTP healthchecks

    cipi health set|unset|check|list — cron every 5 minutes, notify after 3 consecutive failures.

  • 5.0.1 — first-deploy fix

    Guards horizon:terminate when no current symlink exists yet, so brand-new apps deploy cleanly. Migration regenerates existing deploy.php files.

v4.8

4.8.0 → 4.8.1 August 2–3, 2026

The release that made multi-engine databases first-class — MariaDB stays native, PostgreSQL becomes an optional peer — plus cleaner www/apex redirects and SSL redirect recovery.

  • Optional PostgreSQL

    Install with cipi db install pgsql (port 5432). Set the server default with cipi db default, inspect with cipi db engines, and pass --engine=mariadb|pgsql on create / list / delete / backup / restore / password. Laravel apps get matching .env and connection URLs. See cipi db and why PostgreSQL?.

  • www ↔ apex redirects

    cipi www add|force-to-root|force-from-root|clear|status manages canonical 301 redirects and the counterpart host alias. State survives vhost regeneration.

  • SSL force redirect

    cipi ssl force <app> re-applies HTTP → HTTPS without re-issuing the certificate. Alias add/remove also re-applies SSL so HTTPS is not dropped.

  • 4.8.1 — self-update unblock

    Fixes cipi self-update stuck on Migration 4.7.16 (sed delimiter clash), so upgrades from versions below 4.7.16 complete again.
