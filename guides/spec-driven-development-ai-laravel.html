Spec-driven development with AI agents in Laravel

Write the spec first, let an agent implement it against tests, and close the loop on production through MCP, with guardrails that keep data and deploys safe.

By Andrea PollastriUpdated November 23, 20262 min read

Share

AI coding agents are good at implementing a clear, testable specification and bad at guessing what you meant. The teams getting value write the spec first, keep the agent inside guardrails, and give it eyes on production through MCP.

  1. Specwhat and why, acceptance criteria
  2. Testswritten from the spec
  3. Agentimplements until tests pass
  4. Reviewa human, on a preview URL
  5. Productiondeploy, then observe through MCP

1. Write the spec, not the prompt#

A good spec hasExample
The user and the problem"Accountants can't find unpaid invoices quickly"
Acceptance criteria"Filter by status and due date; overdue rows highlighted"
Constraints"No new tables; reuse invoices.paid_at"
Out of scope"No export in this iteration"

Tools like Larapilot structure this with personas and review steps on top of Laravel Boost.

2. Tests before code#

Ask the agent to write Pest tests from the acceptance criteria first, review them, then let it implement until they pass. The tests are the contract.

3. Review on a real URL#

Push the branch and get a preview environment. Reviewers click instead of pulling code; seed it with an anonymized dump so edge cases from real data show up.

4. Close the loop on production#

After the deploy, the same assistant can check the result through the Cipi MCP:

text
You:    Did the invoices release go out cleanly? Any new errors since?
Claude: [deploy_status] Release 134 live, 58 s, from the pipeline.
        [logs level=error since=deploy] None.

Guardrails that matter#

RiskGuardrail
Agent runs destructive SQLMCP SQL guard blocks DDL and multi-statements; CIPI_MCP_DB_WRITE=false
Agent sees personal dataRedaction in outputs; anonymized dumps for experiments
Agent deploys untested codeDeploy only through CI with tests; the MCP deploy tool records who asked
Server config driftscipi.yml changes go through pull requests like code
