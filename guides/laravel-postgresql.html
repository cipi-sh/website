Laravel on PostgreSQL, on your own server

From zero to a Laravel app on PostgreSQL with Cipi: what Postgres is good at, installing it next to MariaDB, creating apps and extra databases on it, connecting from your laptop, backups, restores, upgrades and moving an existing app from MySQL.

By Andrea PollastriUpdated November 23, 20264 min read

Share

PostgreSQL is an open-source database known for being strict, predictable and extensible. Laravel supports it natively: same Eloquent, same migrations, DB_CONNECTION=pgsql. This guide sets it up on a Cipi server, explains what changes compared to MySQL, and covers the day-two tasks.

Key ideas, in plain words#

TermMeaning
EngineThe database server program: MariaDB (MySQL-compatible) or PostgreSQL
DatabaseOne container of tables, e.g. shop
Database userThe login an app uses. On Cipi each app has its own, which owns its database
Superuserpostgres: can do anything. Cipi keeps its password in the encrypted vault
SSH tunnelA way to reach the database from your laptop through SSH, without opening a port
  • Your Laravel appDB_CONNECTION=pgsql, own user
  • PostgreSQLport 5432, localhost only
  • MariaDBport 3306, localhost only, always installed
  • Ubuntu serverfirewall: 22, 80, 443 open

When PostgreSQL is the better choice#

You needPostgreSQL gives you
Rich JSON queriesjsonb columns with GIN indexes; Laravel's whereJsonContains uses them
Safe migrationsDDL runs inside transactions: a failing migration rolls back cleanly
Strict dataNo silent truncation or invalid dates
Advanced indexesPartial, expression and full-text indexes
Extensionspgvector (AI embeddings), PostGIS (maps), pg_trgm (fuzzy search)

Before you start#

  • A Cipi server (install guide) and SSH access as cipi.
  • A Laravel app in a Git repository. Nothing in your code needs to change unless you used MySQL-only SQL (see differences).

1. Install PostgreSQL#

bash
sudo cipi db install pgsql
sudo cipi db engines

Cipi installs postgresql and postgresql-contrib, makes it listen on localhost only, sets a random superuser password in the vault and pins the package so unattended upgrades never restart it. MariaDB keeps running next to it.

Databases
$ cipi db install pgsql
$ cipi db create --name=analytics --engine=pgsql

Want every new app on PostgreSQL by default?

bash
sudo cipi db default pgsql

2. Create a Laravel app on PostgreSQL#

bash
sudo cipi app create --user=shop --domain=shop.example.com \
    --repository=git@github.com:you/shop.git --branch=main --engine=pgsql
Step 1 of 4Linux user

Cipi creates a Linux user named after the app. Files and processes belong to it.

Step 2 of 4Database

A PostgreSQL database with the same name, owned by a database user of the same name, with its own password.

Step 3 of 4.env

The app's .env gets DB_CONNECTION=pgsql, port 5432 and the credentials.

Step 4 of 4First deploy

The first deploy runs your migrations and builds the schema.

Cipi creates the database with UTF8 encoding and gives the app user ownership of it and of the public schema, so migrations can create, alter and drop anything inside it, and nothing outside it.

Check the result:

bash
sudo cipi app env shop --get=DB_CONNECTION
pgsql
sudo cipi db list

3. Extra databases#

An analytics database for the same app, or a database for a tool:

bash
sudo cipi db create --name=analytics --engine=pgsql --app=shop

Add a second connection in config/database.php and the credentials Cipi prints to the app's .env (sudo cipi app env shop).

4. Connect from your laptop#

The database port is never exposed. TablePlus, DBeaver, DataGrip and Postico all support an SSH tunnel:

FieldValue
SSH host / userServer IP, cipi (your SSH key)
Database host / port127.0.0.1, 5432
Database, user, passwordFrom sudo cipi app env shop --show

Or from a terminal:

bash
ssh -L 5433:127.0.0.1:5432 cipi@203.0.113.10
# in another terminal
psql "postgresql://shop:PASSWORD@127.0.0.1:5433/shop"

5. Backups and restores#

bash
sudo cipi db backup shop                     # one-off pg_dump, gzipped
sudo cipi backup profile add hourly-db --scope=db --databases=shop --every=1h --keep=48 --dest=s3 --encrypt
sudo cipi db restore shop /var/log/cipi/backups/shop_20261123_101500.sql.gz

PostgreSQL restores run in one transaction: if the file is truncated or a statement fails, nothing changes and your data stays as it was. Full setup in the backup guide.

6. Upgrades#

bash
sudo cipi db upgrade pgsql

Minor releases (security and bug fixes) install with a brief restart. Plan it outside peak hours, or schedule it with stack upgrades.

MySQL habits that change#

MySQL / MariaDBPostgreSQL
LIKE is case-insensitiveLIKE is case-sensitive: use ILIKE or whereLike(..., caseSensitive: false)
GROUP BY lets you select any columnEvery selected column must be grouped or aggregated
Backticks ` name `Double quotes "name" (Laravel handles this for you)
0000-00-00 dates acceptedRejected: use NULL
Auto-incrementbigserial / identity, same $table->id()
FIELD(), IF()CASE WHEN … END

Raw SQL (DB::raw, whereRaw) is where problems hide: grep for it before switching.

Move an existing app from MySQL#

There's no in-place switch. You create a PostgreSQL app and move the data once:

Step 1 of 5Test locally

Run your test suite against PostgreSQL on your machine and fix raw SQL that only worked on MySQL.

Step 2 of 5New app

Create a second app with --engine=pgsql from the same repository and deploy it: migrations build the schema.

Step 3 of 5Copy data

Copy the data with pgloader (data only) into the tables your migrations created.

Step 4 of 5Check

Compare row counts and click through the important pages.

Step 5 of 5Switch DNS

Move the domain to the new app (or switch DNS). Keep the old app until you're sure.

  1. Run your test suite against PostgreSQL locally (DB_CONNECTION=pgsql in .env.testing) and fix raw queries.
  2. Create shop-pg with --engine=pgsql and deploy: migrations build the schema.
  3. Copy the data. pgloader reads MySQL and writes PostgreSQL directly; install it on the server (sudo apt install pgloader) and run it against both local databases with --with "data only" so it fills the tables your migrations created.
  4. Reset sequences (pgloader does it; for a hand-made import run SELECT setval(...) per table).
  5. Compare row counts, click through the app, then move the domain (sudo cipi app edit shop-pg --domain=shop.example.com after removing it from the old app).

Do a dry run with a copy first, ideally an anonymized one.

pgvector and other extensions#

App users own their database but aren't superusers, so they can't create most extensions themselves. As cipi:

bash
psql --version                                # e.g. 16 on Ubuntu 24.04
sudo apt install postgresql-16-pgvector        # postgresql-<major>-pgvector
sudo -u postgres psql -d shop -c "CREATE EXTENSION IF NOT EXISTS vector;"

After that, migrations can use the vector column type.

Troubleshooting#

ProblemFix
could not find driverRare: Cipi installs php-pgsql with every PHP version. Check php -m as the app user and reinstall the version if it's missing
permission denied to create extensionCreate it as postgres (see above)
column must appear in the GROUP BY clauseAdd the column to groupBy() or aggregate it
Search stopped matching uppercaseLIKE is case-sensitive: use ILIKE
Duplicate key on insert after an importSequences weren't reset
--engine=pgsql refusedPostgreSQL isn't installed yet: sudo cipi db install pgsql

Questions

MariaDB or PostgreSQL for a new app?

Both work with Laravel out of the box. Pick PostgreSQL if you want JSONB, strict types, partial indexes, transactional migrations or extensions such as pgvector; pick MariaDB if your team, hosting or packages expect MySQL.

Can one server run both?

Yes. MariaDB is always there; cipi db install pgsql adds PostgreSQL on port 5432. Each app picks one with --engine, and you can create extra databases on either.

Is the database reachable from the internet?

No. PostgreSQL listens on localhost only and the firewall never opens 5432. You connect from your laptop over an SSH tunnel.

Can I switch an existing app's engine with one command?

No. Create a new app on PostgreSQL and move the data (see the migration section). It's a one-off job you test on a copy first.

Does PostgreSQL get security updates automatically?

It's excluded from unattended upgrades so it never restarts under you. Patch it when you choose with cipi db upgrade pgsql, or schedule it with cipi autoupdate.

Which PostgreSQL version?

The one Ubuntu ships for your release (postgresql package), with postgresql-contrib. cipi db engines shows it.

Can I use pgvector?

Install the extension package for your PostgreSQL version as root, then create the extension in the app's database as the postgres superuser. App users own their database but aren't superusers.
