Cipi Agent: connect your Laravel app to its server

Install cipi/agent to get push-to-deploy, a health endpoint, an MCP server for AI assistants, cipi.yml validation and GDPR-safe database dumps in any Laravel app.

By Andrea PollastriUpdated November 23, 20262 min read

Share

cipi/agent is a Laravel package that lets your app talk to the server it runs on. One composer require and the app gains five features, each behind its own token and each off until you want it.

FeatureEndpoint / commandGuide
Push-to-deployPOST /cipi/webhookWebhook deploys
HealthGET /cipi/healthUptime monitoring
MCP for AI assistants/cipi/mcpClaude, Cursor and the Cipi MCP
cipi.yml toolingphp artisan cipi:ymlcipi.yml
Anonymized dumpsphp artisan cipi:anonymize, /cipi/dbSafe data for developers

Key ideas, in plain words#

TermMeaning
AgentA Composer package inside your app that talks to the server it runs on
ServiceOne feature of the agent (health, MCP, anonymizer…), each off by default
TokenOne secret per service, in the app's .env

1. Install#

bash
composer require cipi/agent
git commit -am "Add Cipi Agent" && git push

On a Cipi server, cipi app create already wrote the .env variables; the service provider auto-discovers. Laravel 12 or 13, PHP 8.3+.

2. Check it after the deploy#

bash
sudo cipi app artisan shop cipi:status

cipi:status shows configuration, environment, live release and commit, enabled features, cipi.yml validity and database connectivity.

3. Turn on what you need#

bash
php artisan cipi:service health --enable && php artisan cipi:generate-token health
php artisan cipi:service mcp --enable && php artisan cipi:generate-token mcp
php artisan cipi:service anonymize --enable && php artisan cipi:generate-token anonymize

Run them as the app user (ssh shop@server) or through sudo cipi app artisan shop …. Each feature has its own token; a disabled feature answers 404, so it's invisible.

4. Use it in CI#

yaml
- run: php artisan cipi:yml validate --json --app=shop

The agent ships the same cipi.yml validator as the server, so a broken file fails the pipeline instead of the deploy.

Agent or API?#

The agent works inside one app, on its domain. The Cipi API runs on its own domain and manages the whole server. Install the PHP SDK next to the agent and the app's MCP gains server-side tools: rollback, database backup, job status.

Troubleshooting#

ProblemFix
cipi:status says not configuredThe .env lacks the CIPI_* keys Cipi writes at creation: compare with a fresh app and add the missing ones
An endpoint answers 404The service is disabled: cipi:service <name> --enable
403 with a valid-looking tokenToken from another service: each has its own
Package refuses to installLaravel 12 or 13 and PHP 8.3+ are required

Questions

Does the agent slow my app down?

No. It adds routes under /cipi/* that are off until enabled, and does work only when called.

Can I change the `/cipi` prefix?

Yes, with CIPI_ROUTE_PREFIX in .env. Update webhooks and monitors that use the old path.

Does it work outside Cipi servers?

The cipi.yml validator and the anonymizer work anywhere; deploy, health and MCP features expect a Cipi server.

How do I remove it?

composer remove cipi/agent, deploy. Routes and tokens go with it.
