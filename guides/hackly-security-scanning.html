Security-test your Laravel apps with Hackly, self-hosted

Install Hackly, a free open-source security scanning platform, as a Cipi app on its own server, prove you own a domain, run DAST scans of your sites and SAST/SCA scans of your repositories, triage findings and export reports, step by step from zero.

By Andrea PollastriUpdated November 23, 20265 min read

Share

Patching servers (which Cipi does for you) is half of security. The other half is checking your own sites and code for weaknesses: exposed paths, weak TLS, missing headers, vulnerable dependencies, leaked secrets. Hackly runs the industry's open-source scanners for you, safely, from one panel.

Key ideas, in plain words#

TermMeaning
TargetA domain you own and want to scan, e.g. shop.example.com
DASTDynamic testing: probing the running site from outside, like an attacker would
SASTStatic testing: reading the source code for dangerous patterns
SCAChecking your dependencies (Composer, npm) for known vulnerabilities
FindingOne problem found, ranked High, Medium or Low
Ownership checkA DNS TXT record proving you control the domain, required before scanning
Step 1 of 5Add target

You register shop.example.com in Hackly. Nothing is scanned yet.

Step 2 of 5Prove ownership

Hackly shows a TXT record. You publish it at your DNS provider and click Check DNS. No proof, no scan: Hackly can't be used against sites you don't control.

Step 3 of 5Scan

Scanners run in the background on Hackly's queue: DNS and TLS, ports, path discovery, Nuclei templates, OWASP ZAP; plus Semgrep, Trivy, Gitleaks, Checkov and Composer audits on linked repositories.

Step 4 of 5Triage

You go through findings by severity and mark each one Acknowledged, Fixed or False positive (with a note).

Step 5 of 5Report

Export a report for your team or your client, or share one finding through a link you can revoke.

Before you start#

  • A separate server for scanning, with Cipi installed: 2 vCPU and 4 GB RAM is a comfortable minimum (OWASP ZAP is Java and memory-hungry).
  • A subdomain such as hackly.example.com pointing at it.
  • Working e-mail (weekly digest, e-mail two-factor codes).
  • A GitHub account to fork Hackly, and (optional) a read-only GitHub token for repository scans.
  • Written permission for every domain you scan that isn't yours.

1. Fork and create the app#

Fork github.com/andreapollastri/hackly, then:

bash
ssh cipi@SCANNER_IP
sudo cipi app create --user=hackly --domain=hackly.example.com \
    --repository=git@github.com:YOU/hackly.git --branch=main \
    --node-build='npm ci && npm run build'

Add the deploy key to your fork, then:

bash
sudo cipi deploy hackly
sudo cipi ssl install hackly
sudo cipi app artisan hackly db:seed --force

The seeded admin is admin@hackly.test / password: change it immediately and enable two-factor authentication.

2. Install the scanners#

The scanners are system programs, installed once as root with Hackly's own scripts. On a Cipi server, become root from the cipi user (su root), then:

bash
# cd /home/hackly/current
# bash scripts/install-scanner-binaries-ubuntu.sh     # dig, whois, nmap, nuclei, nikto, wpscan, ZAP
# bash scripts/install-repo-scanners.sh               # semgrep, trivy, gitleaks, checkov
# exit
sudo cipi app artisan hackly hackly:check-binaries

Missing tools aren't fatal: tasks that need them are skipped and Settings → Scanner health tells you what's missing and how to fix it.

Scan a verified domain with Hackly
$ php artisan hackly:check-binaries
$ php artisan hackly:scan shop.example.com --include-repos --profile=standard

3. Production settings#

bash
sudo cipi app env hackly      # then set:
text
HACKLY_ALLOW_PRIVATE_TARGETS=false      # never scan internal addresses
HACKLY_ALLOWLIST_ONLY=true              # only domains you list…
HACKLY_ALLOWLIST=example.com            # …here
HACKLY_JOB_TIMEOUT=960                  # longer than the slowest scanner (ZAP)
MAIL_MAILER=smtp                        # plus MAIL_HOST, MAIL_USERNAME…
bash
sudo cipi app artisan hackly config:cache
sudo cipi worker restart hackly

Cipi already runs what Hackly needs: a queue worker (scans run there) and the scheduler (Sunday digest, daily scanner database updates, self-updates).

4. Add a target and prove you own it#

Targets → New: enter the domain. Hackly shows the TXT record to publish:

Add it at your DNS provider (Cloudflare: DNS → Add record → TXT). Existing TXT records (SPF and others) stay. Then Check DNS. You can delete the record afterwards.

The scanner's IP is shown on that screen. If the site sits behind a WAF, CrowdSec or Cloudflare rules, allowlist that IP for the duration of the scans, or results will be blocked and incomplete.

5. Run a scan#

ProfileWhat it addsWhen
QuickDNS, mail security (SPF, DKIM, DMARC), TLS, fingerprintFirst look, any time
StandardPorts, path discovery, Nuclei templatesWeekly
DeepOWASP ZAP baselineBefore releases, off-peak

From the CLI: sudo cipi app artisan hackly hackly:scan shop.example.com --profile=standard.

6. Scan your repositories too#

Settings → GitHub tokens: add a fine-grained token with read-only access to the repositories. Then Repositories → New you/shop, and link it to the shop.example.com target. A linked pair is scanned together, and the routes found in the code feed the site scan.

ScannerFinds
SemgrepDangerous PHP and Laravel patterns
Trivy, Composer audit, OSVVulnerable dependencies
GitleaksSecrets committed to Git
CheckovRisky infrastructure files
CheckpointLaravel-specific checks (guide)

7. Triage and report#

StatusMeaning
OpenNeeds a look
AcknowledgedReal, planned
FixedResolved; reopens if detected again
False positiveNot a problem (a note is required)

Export a scan as PDF or Markdown, copy a finding as Markdown or as an AI prompt for your assistant, or share a read-only link you can turn off.

A routine that works#

Step 1 of 4Every push

Code-level checks before anything deploys (Checkpoint guide).

Step 2 of 4Weekly

Hackly scans production and the linked repository; the Sunday digest summarises what changed.

Step 3 of 4Before big releases

ZAP against staging, where heavy traffic doesn't bother anyone.

Step 4 of 4Every night

PHP and services patched by Cipi; Hackly covers what's yours: code, config, dependencies.

Troubleshooting#

ProblemFix
Scan stays queuedHackly's queue worker isn't running: sudo cipi worker list hackly
Tasks skippedScanner missing: Settings → Scanner health, re-run the install scripts as root
Check DNS failsThe TXT record isn't visible yet (wait), or it was added to the wrong name
Few or no web findingsA WAF blocked the scanner: allowlist its IP during the scan
Scan killed after ~15 minutesRaise HACKLY_JOB_TIMEOUT and the queue's retry_after (DB_QUEUE_RETRY_AFTER)
No digest e-mailMail settings, or the scheduler is off: sudo cipi schedule status hackly

Questions

What is Hackly?

A free, open-source (MIT) Laravel app by Andrea Pollastri that runs well-known security scanners (nmap, Nuclei, OWASP ZAP, Semgrep, Trivy, Gitleaks and more) against your domains and repositories, and keeps findings and history in one panel.

Is it legal to scan a site?

Only sites you own or are explicitly authorised to test. Hackly enforces this: a domain must pass a DNS TXT ownership check before any scan starts.

Why a separate server?

Scanners are heavy (ZAP, Nuclei) and send traffic that firewalls may block. A separate scanner keeps production light and gives you one IP to allowlist.

Will scans slow my site down?

Quick and standard profiles are light; deep scans and penetration tests send many requests. Run them off-peak, and against staging first.

What's the difference with Checkpoint?

Checkpoint is a package you run inside your project (and in CI) to check the code before deploying. Hackly scans running sites from outside and repositories from a central panel, on a schedule, and keeps history. Hackly includes Checkpoint among its repository scanners.

Does it fix vulnerabilities?

No. It finds and ranks them, with details you can copy as Markdown or as an AI prompt. Fixing is your job, and Fixed findings reopen if they come back.

Is the compliance page a certification?

No. It scores evidence from your scans against framework checklists as a worksheet. It is not an audit.

How does it update?

Itself, from Settings → Updates, and it understands Cipi's release folders.
