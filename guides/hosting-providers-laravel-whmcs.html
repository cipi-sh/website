Choosing Cipi

For hosting providers: Laravel-ready hosting with Cipi and WHMCS

Laravel developers pay twice today: for a server, and for a panel or platform to run it. A hosting provider that offers Laravel-native hosting keeps both halves of that bill.

By Andrea PollastriUpdated November 24, 20267 min read

Share

Ask a Laravel developer where they host, and the answer is rarely "my hosting provider". It's a VPS plus Forge or Ploi, or a managed platform. The reason isn't price: standard hosting plans don't run what a Laravel app needs. Cipi turns any Ubuntu server into Laravel-native hosting, and its WHMCS module automates the products. This guide is for the hosting company that wants that business.

Laravel-ready VPS: install Cipi at first boot#

Pass the customer's key and run the installer from cloud-init (or your virtualisation panel's post-install script). Without a terminal, the installer asks nothing:

yaml
#cloud-config
runcmd:
  - [bash, -c, 'wget -O - https://cipi.sh/setup.sh | SSH_PUBKEY="ssh-ed25519 AAAA… customer@laptop" bash > /var/log/cipi-install.log 2>&1']

The VM must be full virtualisation (KVM, VMware, Hyper-V, Xen HVM) with Ubuntu 24.04 or 26.04; the installer stops on LXC or OpenVZ.

Architecture#

  • WHMCSorders, invoices, suspensions
  • Cipi modulemodules/servers/cipi
  • Cipi APIone per server, HTTPS + token
  • cipi CLIthe same code as over SSH
  • Isolated appsuser, PHP pool, database, Valkey

Each Cipi server runs its own API, on its own hostname, with a token for WHMCS. WHMCS sees each server as a server in a server group; the module calls the API to create, suspend, unsuspend, change and terminate apps. Your staff can see the whole fleet in the optional web panel.

1. Prepare each server#

bash
wget -O - https://cipi.sh/setup.sh | bash             # fresh Ubuntu 26.04
sudo cipi api api.node1.host.example                   # DNS check, install, certificate
sudo cipi api token create --name=whmcs \
    --abilities=apps-view,apps-create,apps-edit,apps-suspend,apps-delete,deploy-manage,ssl-manage,aliases-view,aliases-create,aliases-delete \
    --expires=2027-12-31

Then let only your own machines reach the API: sudo cipi api ip-whitelist add <WHMCS IP> (and the address of your panel, if you run one). Set up off-site backups and notifications before the first customer arrives.

2. Install the module and add the servers#

your-whmcs/
└── modules/servers/cipi/
    ├── cipi.php
    └── lib/CipiApiClient.php
Step 1 of 5Copy the module

Download it from github.com/cipi-sh/whmcs and copy modules/servers/cipi/ into your WHMCS root. No Composer, no dependencies.

Step 2 of 5Add the server

Module Cipi (Laravel hosting); hostname = the API's base URL without a trailing slash; password = the token; tick Secure so certificates are verified. Set Maximum No. of Accounts to cap apps per server. Use Test Connection.

Step 3 of 5Group the servers

Create a server group per region or tier and choose Add to the least full server, so new orders spread across nodes.

Step 4 of 5Create the product

A hosting product on that group, module Cipi (Laravel hosting): PHP version, app type (laravel or custom), Git repository and branch (for laravel), Auto SSL. Ask for a domain on order.

Step 5 of 5Automate the lifecycle

Turn on suspension and termination for overdue invoices. A suspended app serves a static 503 page and keeps all its data; unsuspending brings it back as it was.

Every call is written to WHMCS's module log (Utilities → Logs → Module Log). If Auto SSL fails because DNS doesn't point at the server yet, the app is still created and the failure is logged: run Install SSL later.

The module's PHP dropdown is a list in cipi_ConfigOptions(). Keep it aligned with the versions installed on your servers (sudo cipi php list), and install a version on every server of the group before selling it.

3. Plans and limits#

Limits stop one customer from starving the others. Set them per app with cipi app limits, or through the API (PUT /api/apps/{name}/limits) from a WHMCS hook, so each product applies its plan automatically:

Plan (example)PHP-FPM childrenmemory_limitQueue workersSoft disk limit
Starter5256M15 GB
Pro10512M220 GB
Business201G450 GB
php
<?php
// includes/hooks/cipi_limits.php — apply the plan's limits after WHMCS creates a Cipi app
if (!defined('WHMCS')) {
    die('This file cannot be accessed directly');
}

add_hook('AfterModuleCreate', 1, function (array $vars) {
    $p = $vars['params'] ?? [];
    if (($p['moduletype'] ?? '') !== 'cipi') {
        return;
    }

    // WHMCS product ID => limits (the fields of PUT /api/apps/{name}/limits)
    $plans = [
        11 => ['fpm_max_children' => 5,  'memory_limit' => '256M', 'worker_procs' => 1, 'disk_limit_gb' => 5],
        12 => ['fpm_max_children' => 10, 'memory_limit' => '512M', 'worker_procs' => 2, 'disk_limit_gb' => 20],
        13 => ['fpm_max_children' => 20, 'memory_limit' => '1G',   'worker_procs' => 4, 'disk_limit_gb' => 50],
    ];
    $limits = $plans[(int) ($p['pid'] ?? 0)] ?? null;
    if ($limits === null) {
        return;
    }

    // The app name the module derives from the WHMCS username
    $app = substr(preg_replace('/[^a-z0-9]/', '', strtolower((string) $p['username'])), 0, 32);
    $base = rtrim((string) $p['serverhostname'], '/');
    if (!preg_match('#^https?://#i', $base)) {
        $base = 'https://' . $base;
    }

    $ch = curl_init($base . '/api/apps/' . rawurlencode($app) . '/limits');
    curl_setopt_array($ch, [
        CURLOPT_CUSTOMREQUEST => 'PUT',
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT => 30,
        CURLOPT_HTTPHEADER => [
            'Accept: application/json',
            'Content-Type: application/json',
            'Authorization: Bearer ' . $p['serverpassword'],
        ],
        CURLOPT_POSTFIELDS => json_encode($limits),
    ]);
    $raw = curl_exec($ch);
    $code = (int) curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);

    // 202 = queued as a job on the server
    logModuleCall('cipi', 'ApplyLimits', ['app' => $app] + $limits, $raw, "HTTP {$code}", [$p['serverpassword']]);
});
LimitControlsNote
fpm_max_childrenConcurrent PHP requestsThe app's metrics count how often it hits the cap: a ready-made upsell signal
memory_limitPHP's per-request memory
worker_procsQueue worker processes
octane_workersOctane workers, for Octane apps
disk_limit_gbSoft limit for files + databaseAlerts at 90% and over the limit; never blocks the site. A repository's cipi.yml can't raise it

For one-off changes, staff can use the CLI (sudo cipi app limits shop --disk=20), the panel, or the PHP SDK: $cipi->limits()->update('shop', ['fpm_max_children' => 10]).

6. Price it#

Cipi adds no licence cost per server, per account or per site, so the margin is the difference between your price and your infrastructure and support.

text
monthly margin per server = apps on the server × price per app − server cost − support time

An example with round numbers, to adapt to your own costs and capacity tests: a node that costs you €60 a month, hosting 20 small Laravel apps sold at €12, brings €240 of revenue and €180 before support. The customer gets a Laravel-native product without a server to manage or a panel to subscribe to; you get a margin no per-account licence eats into.

Questions

Can I sell hosting built on Cipi?

Yes. Cipi and the WHMCS module are MIT: commercial use and resale are allowed, with no per-server or per-account licence. Keep the copyright notice in copies of the code.

Does the module give customers a client area?

No client-area tab. Customers use SSH and SFTP as their app user, Git for deploys, and optionally the Cipi panel, where you can invite them with access to their own app only.

How are one-time credentials delivered?

The module doesn't push them to WHMCS. Deliver them through your onboarding (a ticket, a secure note), or let customers rotate them: cipi db password and SSH keys.

Are disk limits enforced?

They're soft: at 90% and over the limit the monitor alerts you, the site keeps working. Use them to upsell or bill overage, not to break a customer's app at the worst moment.

Can a customer get root?

Not in the managed products: each customer is an isolated app user. Sell a Laravel-ready VPS when they want root.

Does it support email hosting, DNS or reseller accounts?

No. Cipi focuses on applications. Keep your existing mail and DNS products, or partner for them.

Which servers can I use?

Any full virtual machine or bare-metal server with Ubuntu 24.04 or 26.04, a public IPv4 and ports 22, 80 and 443. Containers (LXC, OpenVZ) aren't supported.
