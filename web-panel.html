Web panel · free and self-hosted

Your whole fleet, in the browser.

Apps, deploys, databases, backups, metrics and notifications for every Cipi server, in one panel you host yourself — and the providers around them: Cloudflare, DigitalOcean, AWS, Sentry and 24 more. Give your team and your clients exactly the access they need. Keep the terminal for everything else.

And the providers around your servers

28 connectors for clouds and VPS, DNS, object storage, email, monitoring and security scanners. Paste an API token in Settings, and Cloudflare, DigitalOcean, AWS or Sentry are one click from the apps they serve. The panel already knows your servers, so every address that is one of them says which.

Cloudflare, a zone’s records: 203.0.113.24 → production. Two Cloudflare accounts, one click apart; proxy, export as BIND, cache purge, IP access rules, Workers, Pages, R2 and tunnels on the same page.

Point DNS at a server, by its name

Type production in a record’s value and it’s saved with that server’s IP. The same in every DNS the panel drives: Cloudflare, Route 53, DigitalOcean, Hetzner, Cloud DNS, Azure, OVHcloud, Vultr, Akamai, Scaleway, Porkbun, Gandi and Namecheap.

  • A and AAAA checked against the server’s IPv4 or IPv6
  • Registrars pointed to their Cloudflare zone in one click
  • Any number of accounts per provider

Mail DNS, published for you

A Postmark, Mailgun, Resend or SES domain asks for SPF, DKIM, a Return-Path and MX records. One click writes them into the domain’s Cloudflare zone, on whichever account has it. What’s there is kept; a CNAME pointing elsewhere is reported, never overwritten.

  • The sending key and the app’s .env
  • 30-day figures, bounces, complaints and suppressions
  • Hackly’s ownership records published the same way

Built for the jobs you do every day

Real screens of the panel against its demo servers.

Watch a deploy you didn't start

A push to GitHub, a teammate on the CLI, an assistant over MCP: the app page shows the deploy in progress with its trigger, branch, phase and live log, and holds Deploy and Roll back until it ends.

  • Every deploy recorded with who, where from and how long
  • One click to the log of any past deploy
  • Roll back in a second; migrations stay restorable from snapshots

Read: deploy and roll back

One list for every server

The fleet view puts the apps and databases of every connected server together, with server and type filters, search, and a deploy button on every row. Dashboard cards show CPU, memory, disk and services at a glance.

  • Add servers under Connections with their API token
  • Links carry the server, so they can be bookmarked and shared
  • A phone layout for checks on the go

See what happened, and when

Every minute each server records CPU, memory, load and network, and each app its requests, 5xx, response time, PHP-FPM and queue workers. Seven days at full detail, thirty as 15-minute averages, in a small database on the server itself: no Prometheus, no agent, nothing to host.

  • Charts from the last hour to 30 days, refreshed live
  • Deploys and incidents drawn on every chart
  • 30-day uptime per app and one timeline of events

Zero Trust: sites through Cloudflare, you over a private network

A server can leave no inbound port open. The Zero Trust tab shows the Cloudflare Tunnel as Cloudflare sees it — apps, the panel, the API, databases and SSH — and puts the server on a Tailscale or NetBird network from the browser: paste a key, then close SSH and 80/443 to the world, each with its own button.

  • The tunnel and its replicas, Access on /admin only, service tokens for machines
  • Join Tailscale or NetBird, see the server’s address on it, leave
  • A lock the server would refuse is greyed out, with its reason: nobody gets locked out by a click

Access that matches the job

Invite a client to see their two apps and deploy them, a freelancer to read logs, a teammate to manage a whole server. Each invite is a link that works once and expires in seven days.

A thin layer, not a new control plane

The panel stores no state about your servers. It talks to each one through its API, which runs an allowlist of cipi commands. Remove the panel and every server keeps working exactly as before.

Install it in three commands

Each piece on its own subdomain, pointed at the server. Certificates are issued for you.

Add the API

On every server you want to manage.

sudo cipi api api.example.com

Create a token

Full access for the panel, or a scoped list.

sudo cipi api token create --name=panel --full-access

Install the panel

On one server. Then add connections.

sudo cipi gui panel.example.com
Install the panel
$ sudo cipi api api.example.com
$ sudo cipi gui panel.example.com

Questions

Do I need the panel to use Cipi?

No. Cipi is complete from the CLI. The panel is an optional, self-hosted extra for people who prefer a browser, and you can remove it any time.

Does it cost anything?

No. It's free and open source like the rest of Cipi, and it runs on one of your own servers.

Can one panel manage several servers?

Yes. Add each server's API under Connections: apps and databases of every server appear in one fleet view.

Can I give clients access to only their apps?

Yes. Users see only the servers or apps an admin grants, with separate permissions for deploy, edit, environment, logs, commands and delete.

Is it safe to expose a web panel?

It talks to servers only through their API, checks permissions on every request, supports passkeys, TOTP 2FA and OpenID Connect SSO, and can sit behind Cloudflare Access. Dropping data, Zero Trust changes and installing anything outside a closed catalog of optional packages stay on the CLI by design.

Where does the panel run?

On one of your Cipi servers (or a small dedicated one), at its own subdomain, installed with sudo cipi gui panel.example.com. See Install the panel.

Who can log in?

Users you create, with roles, passkeys (Face ID, Touch ID, Windows Hello, a phone or a security key), optional TOTP two-factor and optional SSO through OpenID Connect. See passkeys and SSO.

Does the panel show metrics and history?

Yes. Each server and app has a Metrics tab: CPU, memory, load, network, requests, errors, response time and workers over the last hour to 30 days, with deploys and incidents marked, 30-day uptime and an events timeline. The data stays on the server. See Metrics.

Can the panel manage notifications?

Yes. The Notifications tab adds, tests, pauses and removes every channel (email, Slack, Discord, Telegram, ntfy, Pushover, webhooks…) and turns each event on or off. See Notifications.

Which providers can the panel connect to?

28, with panel 4.8.0: DigitalOcean, Hetzner, AWS (with S3, SES and CloudWatch), Google Cloud, Microsoft Azure, OVHcloud, Vultr, Akamai (Linode), Scaleway, Contabo and UpCloud; Cloudflare (with R2), Porkbun, Gandi and Namecheap; Johnny, Backblaze B2 and Wasabi; Postmark, Mailgun and Resend; Boogle, Oh Dear, Better Stack, Sentry and Datadog; Aikido and Hackly. Admins add any number of accounts in Settings → Connectors. See Connectors.

Where are the providers' credentials kept?

In the panel's own database, encrypted with its APP_KEY, checked with the provider before they are saved and never sent back to the page. The panel calls the provider directly; your Cipi servers never see those credentials.

Does the panel show Cloudflare Zero Trust?

Yes, read-only. With Cipi 5.16 the server's Zero Trust tab shows the tunnel and its replicas, what is closed, each hostname with its Access paths and people, service tokens, previews, TCP services and SSH certificates. Every change stays on sudo cipi zt. See Zero Trust.

What can't the panel do?

Destructive host operations (deleting databases, removing PHP versions, installing software outside the closed package catalog) stay on the CLI on purpose.

Is it free?

Yes, like the rest of Cipi: MIT licensed, self-hosted, no seats or plans.
